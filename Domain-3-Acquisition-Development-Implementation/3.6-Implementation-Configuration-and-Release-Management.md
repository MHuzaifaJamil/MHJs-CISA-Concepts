# 3.6 Implementation Configuration and Release Management

> **Markers:** 📓 = in my Google Doc notes · ⭐ = frequently tested · ➕ = not in the review manual, verify · unmarked = gap to study. Numbering follows the ISACA CISA Review Manual 28th Ed.

- Rigorous configuration, change, release management for complex IT systems
- Controls attributes of hardware, software, firmware, network connectivity
- Changes assessed, planned, tested, approved, documented, communicated
- Auditor knows tools and SoD between development staff and production
- Tools: ManageEngine Service Desk, SysAid, ServiceNow
### 3.6.1 Configuration management systems
- Maintenance requests documented and approved by change control group (configuration control board)
- Checkpoints, reviews, sign-off at each maintenance stage
- Identify, define, baseline software items across life cycle
- Basis for problem, change, release management
- Configuration management database (CMDB) records hardware and software assets
- Check-out: configuration manager takes item under change control form
- Check-out prevents or manages simultaneous code edits
- Check-in: move item to controlled environment with new version number
- Needs management support and configuration management plan
- Plan covers documentation, test plans, procedures
#### Tool support for change and release management
- Identify items affected by proposed change for impact assessment
- Record configuration items affected by authorized changes
- Implement changes per authorization records
- Register item changes when implemented
- Record release baselines to revert to if change fails
- Prepare release to avoid human errors and costs
#### Baselines
- Build new versions only from baselined items
- Baseline is trusted recovery source
- Base on industry benchmarks (e.g., CIS) ➕
- Least functionality avoids unnecessary vulnerabilities
- Evidence of management commitment to maintenance control
