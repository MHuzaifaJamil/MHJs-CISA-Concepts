# 3.4 Control Identification and Design

> **Markers:** 📓 = in my Google Doc notes · ⭐ = frequently tested · ➕ = not in the review manual, verify · unmarked = gap to study. Numbering follows the ISACA CISA Review Manual 28th Ed.

- Controls ensure authorization, accuracy, completeness of input, processing, output
- Evidence in reports, logs, audit trails
### 3.4.1 Application controls
- Controls over input, processing and output functions
- Only complete, accurate, valid data entered and updated
- Processing does correct task; results meet expectations; data maintained
- Edit tests, totals, reconciliations, exception reporting
- Couple automated controls with manual follow-up of exceptions
- Achieve accuracy, completeness, validity, verifiability, consistency
#### Input / origination controls
- Every transaction entered, processed, recorded accurately and completely once
- Receiving system applies edits, validations, access controls to other systems' output
- Input authorization
  - Verifies transactions approved by management
  - Online authorization or report of items needing manual authorization
  - Signatures on batch forms or source documents
  - Online access controls
  - Unique passwords; MFA; accountability
  - Terminal or client workstation identification
  - Source documents: paper, turnaround document, or online image
  - Input data validation: expected format, no malicious input
- Source document design
  - Preprinted or electronic forms
  - Standard headings, titles, notes, instructions
  - Ease of use and readability
  - Group similar fields
  - Predetermined input codes
  - Cross-reference numbers for tracing
  - Boxes to prevent field size errors
  - Area for management authorization
  - Prenumber to confirm all documents input
- Accountability controls for input
  - SoD: origination, authorization, verification, distribution kept separate
  - Activity reports: volume and hours by user
  - Violation reports: unsuccessful access attempts, terminal, date, time
- Batch controls and balancing
  - Total monetary amount
  - Total items
  - Total documents
  - Hash totals: sums of nonvalue numeric fields
  - Batch header forms are data preparation control
  - Each transaction creates input document
  - All documents batched; all batches submitted and accepted
  - Batch reconciliation and timely correction of differences
  - Controls over resubmission of rejected items
  - Batch registers: record batch totals for comparison
  - Control accounts: reconcile initial edit file totals to master file
  - Computer agreement: compares header totals to calculated totals
- Error reporting and handling
  - Reject only erroneous transactions
  - Reject whole batch
  - Hold batch in suspense
  - Accept batch and flag error transactions
  - Corrections verified, authorized, reentered via normal processing
- Input control techniques
  - Transaction log reconciled to source documents
  - Reconciliation of data
  - Documentation
  - Error correction: logging, timely corrections, upstream resubmission
  - Error correction: approval, suspense file, error file, validity of corrections
  - Anticipation of data receipt
  - Transmittal log
  - Cancellation of source documents (e.g., punching holes)
  - Input sanitization: prevent malicious code injection
#### Processing procedures and controls
- Ensure reliability of application program processing
- Data validation and editing procedures
  - Validate and edit near time and point of origin
  - Preprogrammed input formats
  - Automatic logging of supervisor overrides; non-initiating manager reviews
  - Edit controls are preventive; run before processing
  - Front-end intelligent terminals can edit
  - Sequence check: control numbers in order; duplicates or out-of-sequence rejected
  - Limit check: data not above predetermined amount
  - Range check: within predetermined range of values
  - Validity check: matches predetermined criteria (e.g., status code M or S)
  - Reasonableness check: within reasonable limits or rates
  - Table lookups: match table of possible values
  - Existence check: required valid code present
  - Key verification: keying repeated by second person and compared
  - Check digit: calculated value detects transposition and transcription errors
  - Completeness check: field not blank or zero
  - Duplicate check: new transaction not already entered
  - Logical relationship check: related conditions must hold (e.g., hire date after age 16)
- Processing controls
  - Manual recalculations of sample
  - Editing: tests accuracy, completeness, validity
  - Run-to-run totals across processing stages
  - Programmed controls: detect errors, prompt correct file or version
  - Reasonableness verification of calculated amounts
  - Limit checks on amounts
  - Reconciliation of file totals: manual account, file control record, independent control file
  - Exception reports
- Data file control procedures
  - Data file categories
    - System control parameters: change controlled like program changes
    - Standing data: master data like names and addresses; authorize changes
    - Master/balance data: running balances; strict approval and audit trails
    - Transaction files: validation checks, control totals, exception reports
  - Data file controls
    - Before and after image reporting
    - Maintenance error reporting and handling; reviewed by non-initiator ➕
    - Source documentation retention
    - Internal and external labeling of media; file header records
    - Version usage
    - Data file security
    - One-for-one checking
    - Prerecorded input
    - Transaction logs
    - File updating and maintenance authorization
    - Parity checking: error detection more common than correction
    - Redundancy checking on transmitted blocks; retransmit on mismatch
    - Vertical (column) parity versus horizontal (row, longitudinal) parity
    - Using both parity checks improves detection
  - Direct back-end data fixes
    - Application controls bypassed if database updated directly
    - Needs business authorization for completeness and accuracy
    - Subject to computer operations controls
    - Application controls only as good as controls over back-end fixes
### 3.4.2 Output controls
- Ensure data delivered presented, formatted, delivered consistently and securely
- Logging and storage of negotiable, sensitive, critical forms
  - Reconcile form log to inventory
- Computer generation of negotiable instruments, forms, signatures
  - Compare listing to physical forms; account for rejections and mutilations
- Report accuracy, completeness, timeliness
  - Third-party reporting tools still risky if misconfigured
  - Report specifications, templates and change requests are controls
- Reports generated from the system
  - Auditor validates reports match source data
  - More evaluation after system change or for customized reports
- Report distribution
  - Distribute per authorized parameters; log before distribution
  - Control print spool access, print priority
  - Secure printing, drop-off points, disposal
  - Logical access controls for electronic distribution
- Balancing and reconciling
  - Balance output to control totals; audit trails
- Output error handling
  - Timely error report to originating department
- Output report retention
  - Follow retention schedule and legal regulations
- Verification of receipt of reports
  - Recipient signs log
- Output may be restricted to particular devices (e.g., a printer)

- Implementation: system installed and moved to production after acceptance testing
- End users notified and trained
- System testing occurs
- Data entry or conversion occurs
- Postimplementation reviews occur
