## 3.4.0 Basics: what a control is here

- Definition: a control is a safeguard that reduces the chance of a data error.
- Use: ensures authorization, accuracy and completeness of input, processing and output.
- Audit impact: the IS auditor must identify and understand each control.
- Audit impact: auditor must know how each control is evidenced.
- Evidence comes from reports, logs and audit trails.
- Example: a rejected-transaction report proves an edit check actually fired.

## 3.4.1 Application controls

- Definition: controls built into an application over input, processing and output.
- Use: only complete, accurate, valid data are entered and updated.
- Use: processing does the correct task and results meet expectations.
- Use: data are maintained after processing.
- Audit impact: weak application controls allow bad data into financial reporting.
- Techniques include edit tests, totals, reconciliations and exception reporting.
- Automated controls need manual follow-up to investigate exceptions.
- Audit impact: an exception report nobody reviews is an ineffective control.
- Goals: accuracy, completeness, validity, verifiability and consistency.
- Outcome: data integrity and data reliability.
- Exam traps:
  - Automation alone is never enough; exceptions still need human investigation.
  - Application controls cover input, processing and output, not input only.

### 3.4.1.1 Input / origination controls

- Definition: controls ensuring each transaction is entered, processed and recorded correctly.
- Use: only valid, authorized data enter, and each transaction processes once.
- Scope covers both machine inputs and manual inputs.
- In integrated systems, one system's output is another system's input.
- Audit impact: the receiving system must still apply edits, validations and access controls.
- Example: an interface file from billing is edit-checked before posting to the ledger.
- Exam traps:
  - Trusting another internal system's output without validation is a design weakness.

#### Input authorization

- Definition: verification that management approved every transaction before processing.
- Use: only authorized data are entered for processing.
- Audit impact: controls must keep authorized data unchanged through processing.
- Authorization can be online at entry.
- Alternatively, a report lists items needing manual authorization.
- Signatures on batch forms or source documents evidence authorization.
- Online access controls restrict who may access data or run sensitive functions.
- Unique passwords prevent use of another person's access authorization.
- Unique passwords give accountability for data changes.
- Strong passwords or MFA further strengthen accountability.
- Terminal or workstation identification limits input to specific devices and individuals.
- Identifiers such as serial number or computer name are authenticated by the system.
- Source document: a record of the data being entered.
- Source documents may be paper, a turnaround document or an online image.
- Turnaround document: output from one process reused as input to the next.
- Input data validation: confirms expected format and absence of malicious input.
- Audit impact: lack of input validation exposes the application to injection.

#### Source document design

- Use: well-designed documents raise speed and accuracy of data recording.
- Use: they also control workflow and ease later reference checking.
- Prefer preprinted or electronic forms for consistency and legibility.
- Include standard headings, titles, notes and instructions.
- Layout should emphasize ease of use and readability.
- Group similar fields together to ease input.
- Predetermined input codes reduce errors.
- Cross-reference numbers help research and tracing.
- Boxes prevent field size errors.
- Include an area for management authorization.
- Prenumbering lets you confirm every document was input.
- Audit impact: missing prenumbering weakens proof that all documents were processed.
- Exam traps:
  - Prenumbering supports completeness; it does not prove accuracy of the data.

#### Accountability controls for input

- Where humans are involved, add user-level controls for accountability.
- SoD: no one performs more than one of four duties.
- The four duties: origination, authorization, verification, distribution.
- Audit impact: review job descriptions and authorization levels to test SoD.
- Activity reports show volume and hours by user.
- Audit impact: review activity reports for activity outside authorized hours.
- Violation reports record unsuccessful or unauthorized access attempts.
- Violation reports show terminal location, date and time.
- Audit impact: reports must show managerial review and follow-up.
- Repeated violations may signal attempts to circumvent access controls.
- Exam traps:
  - A violation report without evidence of management review is not effective.

#### Batch controls and balancing

- Definition: grouping input transactions so control totals can be compared.
- Use: confirms the batch processed is the batch submitted.
- Total monetary amount: sum of value fields equals system-processed value.
- Example: invoice values in the batch match total processed sales value.
- Total items: item quantities on documents match items processed.
- Total documents: count of documents in batch matches count processed.
- Hash total: sum of nonvalue numeric fields, such as customer numbers.
- Hash totals have no business meaning on their own.
- Hash totals give assurance on completeness and accuracy of numeric fields.
- Exam traps:
  - Hash totals sum identifiers, not money; monetary totals sum values.
- Batch header forms are a data preparation control.
- Input forms should show the application name and transaction codes.
- Balancing may be manual or automated.
- Totaling must be combined with adequate follow-up procedures.
- Each transaction creates an input document.
- All documents are included in a batch.
- All batches are submitted and accepted by the computer.
- Reconciliation is performed and differences are investigated promptly.
- Resubmission of rejected items is controlled.
- Batch register: records batch totals for later comparison with system totals.
- Control account: compares totals from initial edit file to master file.
- Computer agreement: compares header totals to calculated totals, then accepts or rejects.
- Audit impact: balancing without timely correction of differences is a finding.

#### Error reporting and handling

- Definition: procedures to detect, report and correct input errors.
- Use: only correct data are accepted and errors are recognized.
- Errors arise from duplicated transactions and inaccurate data entry.
- Corrections follow normal processing and are verified, authorized and re-entered.
- Option: reject only the erroneous transactions; process the rest.
- Option: reject the whole batch until corrected.
- Option: hold the batch in suspense pending correction.
- Option: accept the batch and flag error transactions for later correction.
- Audit impact: suspense and error files need ownership and timely clearing.
- Exam traps:
  - Corrections bypassing normal processing and authorization defeat the control.

#### Input control techniques

- Transaction log: detailed list of all updates, manual or automatic.
- Use: reconcile the log to source documents received.
- Reconciliation of data: confirms all received data were recorded and processed.
- Documentation: written evidence of data entry and control procedures.
- Error correction: logging, timely correction, upstream resubmission.
- Error correction: approval, suspense file, error file, validity of corrections.
- Anticipation: user or control group expects data receipt.
- Transmittal log: documents transmission or receipt of data.
- Cancellation of source documents: mark or punch them to prevent duplicate entry.
- Input sanitization: checks user input before storing or using it.
- Audit impact: sanitization prevents malicious code injection.

### 3.4.1.2 Processing procedures and controls

- Definition: controls ensuring reliable application program processing.
- Audit impact: auditor evaluates which exposures the controls cover.

#### Data validation and editing procedures

- Validate and edit input as near origin as possible.
- Preprogrammed input formats put data in the right field and format.
- Supervisor overrides of edits should be logged automatically.
- A manager who did not initiate the override should review the log.
- Edit controls are preventive and run before processing.
- Audit impact: missing or ineffective edits allow inaccurate data to be processed.
- Intelligent front-end terminals can perform edits.
- Data validation finds errors, missing data and inconsistencies among related items.
- Sequence check: control numbers in order; duplicates or out-of-sequence rejected.
- Example: invoices numbered 12001 to 15045; a higher number is rejected.
- Limit check: data must not exceed a predetermined amount.
- Example: payroll cheque over a set ceiling is rejected for authorization.
- Range check: data must fall within predetermined low and high values.
- Example: product codes 100 to 250 only.
- Validity check: data must match predetermined acceptable criteria.
- Example: marital status accepts only M or S.
- Reasonableness check: data compared to expected limits or occurrence rates.
- Example: an order above the usual 20 widgets prints a warning.
- Table lookup: input must match a table of possible values.
- Existence check: a required valid code must be present.
- Key verification: a second person re-keys data and a machine compares.
- Check digit: calculated value added to data to detect alteration.
- Check digit detects transposition and transcription errors.
- Completeness check: field must hold data, not blanks or zeros.
- Duplicate check: new transaction compared with those already entered.
- Example: matching vendor invoice numbers prevents paying a vendor twice.
- Logical relationship check: if one condition is true, related conditions must hold.
- Example: hire date must be over 16 years after birth date.
- Exam traps:
  - Limit check tests a ceiling; range check tests both a floor and ceiling.
  - Validity check tests allowed values; reasonableness check tests plausibility against norms.
  - Completeness check detects blanks; existence check confirms a valid code is present.
  - Check digit targets keying errors, not authorization or fraud.
  - Duplicate check addresses double payment; sequence check addresses gaps and out-of-order numbers.
- ⚠ Check: existence and table lookup overlap; choose by question wording.

#### Processing controls

- Definition: controls keeping accumulated data complete and accurate.
- Use: data remain correct until changed by authorized processing.
- Manual recalculation: recompute a sample to confirm processing does the intended task.
- Editing: program routine testing accuracy, completeness and validity.
- Run-to-run totals: verify data values across processing stages.
- Run-to-run totals confirm read data were accepted and applied to updates.
- Programmed controls: software detecting errors and prompting corrective action.
- Example: a message instructs use of the correct file version.
- Reasonableness verification: checks calculated amounts against predetermined criteria.
- Limit checks on amounts: transactions over limit rejected for investigation.
- Reconciliation of file totals: done routinely on a regular basis.
- Reconciliation uses a manual account, file control record or independent control file.
- Exception reports: program lists data outside range or not meeting criteria.
- Audit impact: reconcile control totals and confirm follow-up of exceptions.

#### Data file control procedures

- Definition: controls ensuring only authorized processing occurs on stored data.
- Data files fall into four categories.
- System control parameters: entries that change how the system works.
- Example: tolerance before an exceptional transaction is blocked.
- Change these like program changes.
- Standing data: rarely changing master data, such as supplier names and addresses.
- Authorize changes before entry; report changes for approval.
- Audit trails may log all standing data changes.
- Master or balance data: running balances updated by transactions.
- Adjust balances only under strict approval and review.
- Audit trails matter because adjustments affect financial reporting.
- Transaction files: use validation checks, control totals and exception reports.
- Audit impact: parameter changes without change control can silently weaken controls.

##### Data file controls

- Before and after image reporting: records file data before and after each transaction.
- Use: traces the impact of transactions on records.
- Maintenance error reporting and handling: errors reconciled and corrected promptly.
- Corrections should be authorized by someone who did not initiate them.
- ⚠ Check: the outline marks this ➕, but the manual does support it.
- Source documentation retention: keep long enough to retrieve, reconstruct or verify data.
- Destroy source documents securely when appropriate.
- Internal and external labeling: ensures correct media and files are loaded.
- External labels give basic assurance; internal labels allow automated checking.
- File header records are internal labels.
- Version usage: right file and version must be used for processing.
- Example: transactions apply to current data; restarts use earlier versions.
- Data file security: stops unauthorized changes to stored data.
- It does not assure validity of the data.
- One-for-one checking: documents agree with the computer's detailed processed listing.
- Use: confirms all documents were received for processing.
- Prerecorded input: preprinted fields on blank forms reduce input errors.
- Transaction logs: record date, time, user ID and terminal location of input.
- Use: audit trail; speeds exception research and recovery after failure.
- File updating and maintenance authorization: proper approval keeps stored data correct.
- Parity checking: check bits detect transmission errors.
- Error detection is used more often than correction.
- Reason: correcting codes are costly and cannot fix all errors.
- Redundancy checking: receiver checks character counts or bit patterns of a block.
- On mismatch, the receiver ignores data and requests retransmission.
- Vertical parity: check on a single character, also called column check.
- Horizontal parity: check on equivalent bits, also called row or longitudinal check.
- Using both checks greatly improves detection of transmission errors.
- Exam traps:
  - Data file security protects against unauthorized change, not invalid data.
  - Parity detects errors; it does not correct them.

#### Direct back-end data fixes

- Definition: updating the database directly, bypassing the application front end.
- Application controls are bypassed when the database is updated directly.
- Valid case: backlog after a system outage.
- Audit impact: business must authorize fixes for completeness and accuracy.
- Audit impact: fixes must follow computer operations controls.
- Application controls are only as good as back-end fix controls.
- Example: managers editing the database directly override the best application controls.
- Exam traps:
  - The auditor does not ban back-end fixes; they must be authorized and controlled.

## 3.4.2 Output controls

- Definition: controls assuring data reach users formatted, consistent and secure.
- Use: protect confidentiality, accuracy and completeness of delivered output.
- Logging and storage of negotiable, sensitive and critical forms: log and secure them.
- Reconcile the form log to inventory on hand.
- Research discrepancies properly.
- Computer-generated negotiable instruments, forms and signatures need strict control.
- Compare the generated listing to physical forms received.
- Account for exceptions, rejections and mutilations.
- Example: blank cheque stock is logged and reconciled to cheques printed.
- Report accuracy, completeness and timeliness matter even with accurate sources.
- Third-party reporting tools still risk misconfigured reports.
- Report specifications, templates and change request processes are key output controls.
- Reports from the system support management decisions.
- Audit impact: the auditor validates reports match source data.
- Audit impact: do more evaluation after system change or for customized reports.
- Report distribution: follow authorized distribution parameters.
- Log reports before distribution.
- Operations verify reports are complete and on schedule.
- Control print spool access to prevent deletion or redirection.
- Control print priority changes that could delay critical jobs.
- Print sensitive reports under secure, controlled conditions.
- Establish secure drop-off points and secure disposal.
- Apply logical access controls to electronic distribution.
- Balancing and reconciling: balance output routinely to control totals.
- Provide audit trails for tracking and reconciling.
- Output error handling: send timely error reports to the originating department.
- Output report retention: follow the retention schedule firmly.
- Include governing legal regulations in the retention policy.
- Verification of receipt: recipient signs a log for sensitive reports.
- Output can be restricted to particular devices, such as one printer.
- Exam traps:
  - Spool access and print priority are output controls, not input controls.
  - Signed receipt log proves delivery, not report accuracy.
  - Retention periods come from schedule and law, not storage convenience.

## Takeaway

- Application controls span input, processing and output, with manual exception follow-up.
- Match each edit check to its error type: limit, range, validity, reasonableness.
- Batch totals prove completeness; hash totals sum non-value fields only.
- Application controls are only as good as back-end fix controls.
- Output controls secure distribution, reconciliation, retention and proof of receipt.
