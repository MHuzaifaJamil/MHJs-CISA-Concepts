# 5.14 Security Incident Response Management

> **Markers:** 📓 = in my Google Doc notes · ⭐ = frequently tested · ➕ = not in the review manual, verify · unmarked = gap to study. Numbering follows the ISACA CISA Review Manual 28th Ed.

- Not all incidents are computer-related; burglary is an incident
### 5.14.1 Incident response process
- Preparation
  - Define an incident
  - Create incident response policy
  - Develop procedures (SOPs)
  - Establish communication guidelines
  - Define incident response activities
  - Select incident response team
  - Establish notification mechanisms
  - Prevention: patching, hardening, perimeter
- Detection and analysis
  - Hardest phase: accurately detecting and assessing incidents
  - Sources: IDS/IPS, antivirus, log analyzers, user reports
- Containment, eradication and recovery
  - Containment: shut down, disconnect, disable functions
  - Separate containment strategy per incident type
  - Eradication: delete malicious code, disable breached accounts
  - Recovery: restore from clean backups, rebuild, patch, change passwords
  - Recovery: tighten perimeter
- Postincident activity
  - Lessons-learned review
  - Identify systemic weaknesses
  - Feed training and awareness ➕
### 5.14.2 Computer Security Incident Response Team (CSIRT)
- Clear lines of reporting; standby support
- Responsibilities
  - Determine amount and scope of damage
  - Determine information compromise
  - Implement recovery procedures
  - Supervise additional security measures
- Acts as detective, corrective and preventive control
- Single point of contact for incidents
- Common issues: virus outbreak, web defacement, abuse notification
- Common issues: unauthorized access, IDS/IPS alerts, theft, root compromise
- Common issues: physical breach, malware, defamatory media, forensic investigations
### 5.14.3 Incident response plan
- Automate repetitive tasks
- Leverage templates and playbooks
- Centralize IR initiatives
- Test the plan
- Invest in IR training
- Standardize incident response
- Obtain executive buy-in
- Confirm roles and responsibilities; backups
- Document critical assets
- Establish crisis communications plan; pre-approved messages
### 5.14.4 Security Orchestration, Automation and Response (SOAR)
- Components
  - Orchestration: connects security tools
  - Automation: removes manual tasks
  - Response: coordinates reaction to threats
- Benefits of SOAR
  - Promotes security visibility
  - Reduces security costs
  - Improves security efficiency
  - Improves security effectiveness
  - Promotes security flexibility
  - Enhances collaboration
  - Streamlines security operations
- SOAR vs SIEM
  - SIEM only alerts; SOAR adds automation and response
  - SOAR aggregates more sources: endpoint, cloud, IoT
