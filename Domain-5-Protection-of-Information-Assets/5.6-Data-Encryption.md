# 5.6 Data Encryption

> **Markers:** 📓 = in my Google Doc notes · ⭐ = frequently tested · ➕ = not in the review manual, verify · unmarked = gap to study. Numbering follows the ISACA CISA Review Manual 28th Ed.

- Encryption converts plaintext to ciphertext using key
- Uses
  - Protect data in transit
  - Protect stored information
  - Deter and detect alteration
  - Verify authenticity of transaction or document
- Cannot prevent loss or modification of data; key protection paramount
- Subject to national laws and regulations
### 5.6.1 Elements of encryption systems
- Encryption algorithm
- Encryption key
- Key length: longer resists brute force
- Brute force attack: tries all possible keys
- Cryptanalysis: finds algorithm weaknesses
- Known plaintext attack
- Key randomness: weak passwords shrink key space
- Symmetric key: one secret key, shared out of band
- Asymmetric key: public key encrypts, private key decrypts
- Hash functions
  - One-way, fixed-length digest
  - Detect single-bit change
  - MD5: 128-bit; SHA-1: 160-bit; SHA-512: 512-bit
  - Industry moving to SHA-2; SHA-3 announced by NIST
- Encryption vs hashing
  - Encryption two-way, variable length, uses keys
  - Hashing one-way, fixed length, no keys; salt can be added
  - Encryption algorithms: AES, RC4, DES, RSA
  - Hashing algorithms: SHA-1, SHA-2, MD5
  - Salt defends against dictionary and rainbow table attacks
- Message integrity check: compare sender digest to receiver digest
### 5.6.2 Link encryption vs end-to-end encryption
- Link encryption (online encryption)
  - Encrypts all traffic on a channel, including headers and routing data
  - Works at data link and physical layers
  - Decrypted and re-encrypted at each hop
  - Advantage: simple, user not involved
  - Disadvantage: key distribution to each hop; hop vulnerabilities
- End-to-end encryption (E2EE)
  - Message encrypted from origin to destination
  - Headers and routing information not encrypted
  - User chooses what to encrypt
  - Example: WhatsApp
### 5.6.3 Symmetric key cryptographic systems
- Same key encrypts and decrypts
- DES withdrawn; 3DES extended it
- AES replaced DES in 2001; 128 to 256-bit keys
- RC4: stream cipher used in SSL/TLS
- Advantages: shorter keys, less processing, suited to bulk data
- Disadvantages: key distribution difficult; cannot sign documents
### 5.6.4 Public (asymmetric) key cryptographic systems
- Key pair: public and private, based on integer factorization
- One key pair per direction
- Solves key distribution; 2N keys vs about N squared symmetric
- RSA: first practical system; keys 1024 to 4096 bits
- RSA drawback: key length and computation
### 5.6.5 Elliptic curve cryptography
- Based on elliptic curves over finite fields
- Smaller keys than RSA for equal security
- Faster key generation, key agreement, signatures
- More bandwidth savings than RSA
### 5.6.6 Quantum cryptography
- Uses photons over fiber optic cables
- Quantum key distribution (QKD) detects eavesdropping
- Benefits
  - Secure communication by laws of physics
  - Protects against eavesdropping
  - Variety of security methods
  - Simple to operate
- Limitations
  - Polarization changes
  - Limited range, about 500 km
  - High implementation costs
  - Limited destination range; no multiplexing
### 5.6.7 Homomorphic encryption
- Mathematical operations on encrypted data
- Benefits
  - Supply chain security
  - Cloud data security
  - Data security
  - Regulatory compliance (GDPR)
  - Data analytics
  - Privacy
- Types and challenges
  - Partially homomorphic: infinite operations of one type; RSA is example
  - Somewhat homomorphic: finite number of any operation
  - Fully homomorphic: infinite additions and multiplications; goal
  - Challenge: inefficiency
  - Challenge: high storage requirements
  - Challenge: reduced performance
  - Challenge: inability to scale
  - Challenge: large complex algorithms
### 5.6.8 Digital signatures ⭐
- Private key encrypts digest; public key verifies
- Digest (pre-hash) compared with post-hash
- Ensures data integrity
- Ensures authentication
- Ensures nonrepudiation
- Replay attack: prevented by timestamp or counter
- Non-repudiation: sender cannot deny sending 📓⭐
### 5.6.9 Digital envelope
- Message encrypted with symmetric key
- Symmetric key encrypted with receiver's public key
- Example: Pretty Good Privacy (PGP)
### 5.6.10 Applications of cryptographic systems
- Combined scheme: symmetric speed plus asymmetric key distribution
- Used in SSL/TLS and S/MIME
- Transport Layer Security (TLS)
  - Phase: peer negotiation of algorithms
  - Phase: public-key key exchange and certificate authentication
  - Phase: symmetric cipher traffic encryption
  - Public-key choices: RSA, Diffie-Hellman, DSA, Fortezza
  - Symmetric choices: RC4, IDEA, Triple DES, AES
  - Hash choices: SHA-1, SHA-2
  - Runs above TCP; HTTPS
  - B2B: client and server authenticated; B2C: server only
  - Handshake Protocol: negotiates and establishes connection
  - Record Protocol: encrypts and authenticates packets
  - SSL replaced by TLS after 2014 vulnerability
- IP Security (IPsec)
  - IP network-layer protocol for VPNs
  - Transport mode: encrypts ESP payload (data)
  - Tunnel mode: encrypts ESP payload and header
  - Authentication header (AH) adds nonrepudiation
  - Encapsulating security payload (ESP)
  - Steps: check policy, negotiate, exchange data, end session
- Security association
  - One-way connection negotiating ESP or AH parameters
  - Identified by 32-bit security parameter index (SPI)
  - Managed by ISAKMP; IKE handles key management
  - Contains keys, algorithms, endpoint identities
### 5.6.11 Kerberos
- Ticket authentication via trusted third party; SSO
- Kerberos 5 uses AES
- Protects against eavesdropping and replay
- Components
  - Key Distribution Center (KDC)
  - Ticket-Granting Server (TGS)
  - Authentication Server (AS)
  - Ticket-Granting Ticket (TGT)
  - Service Ticket (ST)
- Logon steps
  - User logs on; client encrypts username to KDC
  - KDC verifies, issues symmetric key and TGT
  - Client decrypts key with password hash
  - Client sends TGT to TGS for service ticket
- Password never sent over network
- Risk: KDC single point of failure
- Risk: strict time requirements; clock drift invalidates TGT
### 5.6.12 Secure Shell (SSH)
- Encrypted remote command-line sessions; replaced Telnet
- Application layer; client-server
- Uses: remote logon, file transfer, remote command execution
- SSH key security best practices
  - Centralize key management; avoid key sprawl
  - Change default SSH port
  - Disable SSH root login
  - Key attribution to individuals
  - Key rotation
  - Continuous audits of privileged sessions
  - Firewall allowlisting, rate blocking, port knocking
### 5.6.13 DNS Security Extensions (DNSSEC)
- Adds digital signatures to DNS records
- Provides origin authentication, authenticated denial of existence, data integrity
- Two stages: signing and validation
- Prevents DNS cache poisoning
- Prevents DNS false zones
- Vulnerabilities
  - DDoS amplification
  - More query responses
  - UDP reliance: faster but riskier; no handshake, easily intercepted
### 5.6.14 Email security
- Common email attacks and techniques
  - Bombing: repeated identical messages
  - Spamming: spam managed by SPF, Bayesian filtering, grey listing
  - Responding to spam validates address
  - Spoofing: forged sender
  - Business email compromise (BEC): targets finance staff
- Email security technologies (Figure 5.35)
  - S/MIME: X.509 certificates, signing and encryption
  - MIME Object Security Services (MOSS): rarely used
  - Privacy Enhanced Mail (PEM): RSA and DES, X.509
  - DomainKeys Identified Mail (DKIM): domain signature, detects forged senders
  - Pretty Good Privacy (PGP): open source
- Email security controls
  - Secure email gateway (SEG)
  - Email attachment control (EAC)
  - Spam filters
  - Email encryption
  - Antivirus protection
### 5.6.15 Encryption audit procedures
- Encryption policy
  - Written policies and procedures
  - Data classification system
  - Regular encryption risk assessments
  - No duplicated encryption
  - Dual control and separation of duties
  - Compliance with data protection rules
  - Audit system for encryption
- Encryption design
  - Algorithm selection effective and documented
  - Standards such as TLS applied
  - Compatible with applications
  - Key length, composition, management per policy
- Key management
  - Controlled changes by authorized individuals
  - Written key transmission procedure
  - Key creation, rotation, destruction per policy
  - Users and operators do not handle keys
- Digital signatures
  - Private keys never backed up
  - Different key pairs for encryption and signatures
- Encryption algorithms
  - Cost of deciphering exceeds information value
- Full disk encryption protects lost or stolen devices 📓⭐
