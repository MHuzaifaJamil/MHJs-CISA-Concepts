# 5.13 Security Monitoring Logs, Tools and Techniques

> **Markers:** 📓 = in my Google Doc notes · ⭐ = frequently tested · ➕ = not in the review manual, verify · unmarked = gap to study. Numbering follows the ISACA CISA Review Manual 28th Ed.

### 5.13.1 Information security monitoring
- Reviewing information to detect malicious activity, intrusion attempts, failures
- Log analysis: systematic review for trends and patterns
- Benefits
  - Enforces accountability
  - Promotes positive behavior
  - Encourages compliance culture
  - Supports investigations; NTP keeps timestamps consistent
  - Identifies security problems
### 5.13.2 Intrusion Detection Systems (IDS)
- Complements firewalls; monitors network anomalies
- Network-based IDS
  - Between Internet and firewall: sees all attack attempts
  - Between firewall and corporate network: sees attacks that enter
- Host-based IDS
  - Monitors OS resources; detects executable changes, file deletion, privileged commands
- Components: sensors, analyzers, administration console, user interface
- IDS types
  - Signature-based
  - Statistical-based
  - Neural networks: self-learning
  - Combining signature and statistical models gives better protection
- Features, limitations, policy
  - Features: detection, evidence gathering, automated response, security policy
  - Limitations: policy weaknesses, application-level vulnerabilities, back doors, I&A weaknesses
  - Policy action: terminate the access
  - Policy action: trace the access
  - Management predefines action
- Internal IDS behind the firewall detects attacks that pass the perimeter 📓
- IDS inside the boundary watches traffic crossing the perimeter 📓
### 5.13.3 Intrusion Prevention Systems (IPS)
- IPS tries to stop attacks; IDS only alerts
- IPS needs proper tuning; thresholds matter
- IPS itself can be abused to disrupt hosts
- IPS types
  - Host-based IPS (HIPS)
  - Network-based IPS (NIPS)
  - Wireless IPS (WIPS): detects rogue APs
- IDS vs IPS
  - IDS monitors; IPS accepts or rejects packets
  - IPS can do IDS job; not vice versa
  - IPS sits at firewall juncture; IDS across network
  - IPS can block zero-day without signatures
- Honeypots and honeynets
  - Honeypot: decoy vulnerable server; does not protect
  - High-interaction honeypot: real environment
  - Low-interaction honeypot: emulates production
  - Honeynet: linked honeypots simulating larger network
  - All honeypot traffic assumed suspicious
  - Risk: external services may flag organization as vulnerable
- Best practices for IDS/IPS implementation
  - Perform asset inventory
  - Establish IDS/IPS policy
  - Set a baseline
  - Proper placement: highest visibility first
  - Ongoing tuning
  - Develop logging systems
  - Order of deployment: network-based first, then host-based
  - Incident response plan
### 5.13.4 Audit logging in monitoring system access
- Access control software logs access attempts; keystroke logging for privileged users
- Log issues: what is logged, who accesses logs, retention
- Access rights to system logs
  - Strictly controlled
  - Protect integrity: digital signatures, write-once devices, SIEM
  - Confidentiality: strong access controls, encryption
  - Media logging supports accountability
- Tools for audit trail (log) analysis
  - Audit reduction tools
  - Trend/variance-detection tools
  - Attack-signature-detection tools
  - SIEM systems
- Cost considerations
  - System overhead
  - Storage and processing
  - Analysis time
  - Investigating anomalous events
- Violation follow-up
  - Look for patterns of privilege abuse
  - Refer violations to security administrator
  - Executive management decides on notifying law enforcement
  - Manage public relations and press
  - Written violation guidelines
  - Formal, consistent disciplinary action
  - Review access rules; remove excessive access
### 5.13.5 Protecting log data
- Centralize log storage
- Implement access controls: append-only
- Restrict logging of sensitive data
- Establish log policies: backup and retention
- Secure log transfer: IPsec, TLS
- Secure storage media
- Protect archived logs: message digests, encryption
- Log disposal controls; avoid data remanence
### 5.13.6 Security Information and Event Management (SIEM)
- Correlates events into incidents
- Rule-based vs statistical correlation
- Combines SIM (historic logs) and SEM (real-time)
- Log collection: agentless or agent-based
- Benefits, features, implementation best practices
  - Benefit: enhances analytics
  - Benefit: enhances regulatory compliance
  - Benefit: faster response with SOAR
  - Benefit: supports investigations
  - Benefit: improves threat intelligence
  - Benefit: insight into past events
  - Benefit: real-time attack detection
  - Benefit: reduces security staffing
  - Feature: policies
  - Feature: security knowledge base
  - Feature: log data management
  - Feature: event correlation and analytics
  - Feature: notifications and alerts
  - Feature: network visibility
  - Feature: security incident monitoring
  - Feature: compliance reporting
  - Practice: set implementation scope
  - Practice: provide holistic posture
  - Practice: identify compliance requirements
  - Practice: classify digital assets
  - Practice: fine-tune configurations
  - Practice: implement IRP
  - Practice: automate and integrate
  - Practice: assign SIEM administrator, consider MSSP
  - Practice: monitor access controls
  - Practice: test the SIEM
### 5.13.7 Security monitoring tools
- Monitor, detect, analyze system and network activity
- Provide alerts, metrics, traffic analysis, visualizations
