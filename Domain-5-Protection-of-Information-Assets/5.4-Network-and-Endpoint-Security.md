# 5.4 Network and Endpoint Security

> **Markers:** 📓 = in my Google Doc notes · ⭐ = frequently tested · ➕ = not in the review manual, verify · unmarked = gap to study. Numbering follows the ISACA CISA Review Manual 28th Ed.

- Perimeter controls prevent and detect most attacks: firewalls and IDSs at trusted/untrusted borders
### 5.4.1 IS network infrastructure
- Telecom links classified by provider or technology
- Dedicated circuit (leased line) vs switched circuit
- Packet switching: users share carrier resources; cheaper than leased lines
- Virtual circuits connect customer sites across carrier cloud
- Packet-switching examples: ATM, SMDS
- Baseband: signal directly on link, one channel, half-duplex
- Broadband: multiple carrier frequencies, full-duplex
### 5.4.2 Enterprise network architectures
- Network segments by function: web front-end, application, database, mainframe servers
- Terminal emulation to legacy back-end systems
- Service-oriented architecture (SOA): SOAP and XML components, loosely coupled
- Auditor needs LAN and WAN specification knowledge
### 5.4.3 Types of networks
- Personal area network (PAN)
  - Range about 33 feet (10 meters)
  - Wired: USB
  - Wireless PAN: IrDA, Bluetooth piconet
  - Piconet: up to eight active devices, master-slave
- LAN: limited area, high data rates; Ethernet and Wi-Fi
- Storage area network (SAN)
  - Dedicated network, block-level storage
  - NAS provides file-level storage; SAN spans many device types
  - SAN risk: physical threats, weak authentication, lateral movement
  - Control: strong frequent authentication; departments protect own data
- Wide area network (WAN)
  - Covers city, region, nation; Internet is largest WAN
  - Wireless WAN (WWAN)
  - Metropolitan area network (MAN): city-limited, higher rates
### 5.4.4 Network services
- Network file system
- Email services
- Print services
- Remote access services
- Directory services
- Network management
  - Status of line, terminals, message queues, error rate, traffic
  - Early warning of problems
- DHCP: assigns IP address, gateway, subnet mask, DNS addresses; leases ensure uniqueness
- DNS: translates node names into IP addresses
### 5.4.5 Network standards and protocols
- Reference model for structuring communication
- Challenges standards address
  - Interoperability
  - Availability (24/7)
  - Flexibility and scalability
  - Maintainability
- FTP is high risk: cleartext and complex ports 📓⭐
- SMTP, SOAP, HTTP (compare risk) ➕
### 5.4.6 Virtual Private Networks (VPN) 📓
- Encrypted packets over public Internet virtual connections
- Platform independent; only remote software needed
- VPN types
  - Remote-access VPN: telecommuters and mobile users
  - Intranet VPN: branch offices
  - Extranet VPN: business partners, each manages own VPN
- VPN primary issues
  - Transmission security: hijacking, malware entry
  - Managing technology
  - Configuration management
  - Information unaltered and reliable
- VPN protocols
  - IPSec: tunnel mode encrypts whole packet; transport mode encrypts data only
  - IKEv2: re-establishes lost connections; good for mobile
  - PPTP: security vulnerabilities, needs compensating controls
  - SSTP: PPP over SSL via HTTPS, passes firewalls and proxies
  - L2TP: relies on IPSec transport mode (L2TP/IPsec)
  - L2TP/IPsec supports perfect forward secrecy
  - OpenVPN: open source, SSL/TLS key exchange, traverses NAT and firewalls
- VPN best practices
  - Establish VPN policy
  - Standards-based VPN (IKE/IPSec over custom SSL/TLS)
  - Strong cryptography: TLS 1.3, AES 256-bit, FIPS-validated
  - Strong authentication: MFA, client certificates, tokens
  - Practice patch management
  - Strict access control: UDP ports 500 and 4500 for IKE/IPsec; IP allowlist
  - Block management interfaces through VPN
  - VPN does not inspect traffic; pass through WAF and IDS/IPS
  - Harden configuration
  - VPN cannot stop malware; use company hardware with antimalware
  - Test VPN capabilities; extra security adds latency
  - Monitor and log VPN usage
- VPN protects data on public Wi-Fi 📓
### 5.4.7 Network Attached Storage (NAS)
- Centralized file server for file sharing
- NAS vulnerabilities
  - Unsecure network configurations
  - Unsecure passwords
  - Insufficient authentication
  - Leakage from other network devices (IoT)
  - Exposure to malware, ransomware
  - Command injection
- NAS best practices
  - Train employees on social engineering
  - Update OS and firmware
  - Secure Internet connections and ports
  - Manage passwords securely
  - Enable MFA
  - Use HTTPS
  - Enable firewall allowing trusted sources only
  - Use VPN to connect
### 5.4.8 Content Delivery Networks (CDN)
- Distributes content across geographically spread proxy servers 📓
- Improves availability, helps against DDoS 📓
- Requests go to nearest server; cache hit returns, miss goes to origin
- Benefits, security risk, best practices
- Content types
  - Dynamic content (PHP, Java)
  - Static content (images, CSS, JavaScript)
  - Streaming content (video, audio)
- Benefits
  - Improved user experience, lower bounce rate
  - Global accessibility
  - Scattered points of presence (PoPs)
  - Automatic data analytics
  - Lower network congestion
  - Increased content quality
  - Lower overhead costs
- Security risk
  - Session hijacking
  - Credential theft from shared cache
  - Distributed DoS attacks
  - Compromised CDN server modifies cached content
  - Performance risk
  - Increased cost profile
  - Loss of control
- Best practices
  - Careful CDN evaluation
  - Implement a WAF
  - SSL certificate compatibility
  - Proper content routing, country restrictions
  - Content deletion and caching controls
  - DR/BC procedures
### 5.4.9 Network Time Protocol (NTP)
- Synchronizes clocks; runs on UDP at application layer
- Supports Kerberos and log correlation
- Benefits
  - Improves security
  - Reduces spoofing attacks
  - Improved accuracy
  - Easy configuration
  - Improved availability
  - Improved reliability with redundant servers
  - Improved network management
  - Improved compliance: traceable time source
- NTP risk
  - Weak security options: MD5, SHA-1, Autokey insecure
  - Continued spoofing of clients
  - Added fake UDP fragments
  - Kiss-of-death (KoD) attacks
  - Time-dependent security protocols: replay attacks if time set back
  - Unprotected NTP lets attacker change log sequence
- Best practices for NTP (supports log timestamp sync 📓)
  - Use public NTP for external hosts
  - Hierarchical configuration: Stratum 0/1 appliances
  - Standardize on UTC
  - Evaluate need for cryptography
  - Use at least two servers
  - Limit strata levels
  - Monitor server functionality, GPS signal loss, SNMP
### 5.4.10 Applications in a networked environment
- Client-server technology and security
  - Client-server: servers provide services, clients consume
  - Work split between client and server
  - Thin client: depends on server for processing
  - Thick (fat) client: processes locally
  - Two-tier: thick client plus database servers
  - Two-tier drawbacks: client synchronization, limited scalability
  - Three-tier: thin client, application servers, database servers
  - Three-tier advantages: cheaper clients, scalability, separated logic
  - N-tiered: more complex to build and maintain
  - Sequence diagrams in UML describe interaction
  - Client-server security depends on LAN, client, OS, database, middleware
  - Two-tier gap: database accounts bypass application controls
  - Two-tier gap: proxy user password stored insecurely
  - Auditor: application controls not bypassed, passwords encrypted
  - Auditor: minimal and audited access to configuration files
- Middleware
  - Glue between applications; provides identification, authentication, authorization
  - Transaction processing (TP) monitors: load balancing
  - Remote procedure calls (RPC)
  - Object request broker (ORB): CORBA, COM/DCOM
  - Messaging servers
  - Risk: system integrity across multiple environments
  - Controls: testing, approval, authorized changes, version control
- On-demand computing
  - Utility computing: resources allocated by need
  - Benefit: no payment for excess capacity
  - Concern: confidentiality at third-party provider

### 5.4.12 Firewalls 📓
- Device at point where network connections enter a site; applies traffic rules
- Firewall general features
  - Block access to particular sites
  - Limit traffic on public segment to relevant addresses and ports
  - Prevent certain users reaching certain servers
  - Monitor and record communications
  - Encrypt packets between sites via VPN
  - Extended: virus and OS-exploit protection
  - Deny-all philosophy: denied unless business reason
  - Accept-all philosophy: allowed unless reason to deny
- Firewall types
  - Three ORM categories: packet filtering, application firewall systems, stateful inspection
  - Packet filtering firewall: inspects packets against ACLs 📓
    - First generation; screening router examines headers
    - Uses IP addresses and port numbers
    - Advantage: simple, stable performance at network layer
    - Weakness: improperly configured filters, attacks tunneled over permitted services
    - Weakness: compromised router exposes all systems
    - Attack: IP spoofing
    - Attack: source routing specification
    - Attack: miniature fragment attack
  - Stateless firewall: static header information only 📓
  - Stateful firewall: tracks connection state 📓
    - Tracks destination IP of outbound packets, matches responses
    - Efficient at transport layer; complex to administer
  - Next Generation Firewall: deep packet and application inspection 📓
    - Application awareness
    - Deep packet inspection (DPI)
    - Integrated IDS/IPS
    - High performance
    - Threat intelligence
    - Antimalware
    - Firewall as a Service (FWaaS): cloud-based
    - Benefits: robust security, intelligent automation, streamlined architecture
  - Application firewall systems
    - Application-level gateway: one proxy per service
    - Circuit-level gateway: single general-purpose proxy; rare
    - Bastion host handles incoming requests
    - Proxy hides internal network; NAT maps private to public IPs
    - Disadvantage: poor performance and scalability
  - Web Application Firewall
    - Protects web apps; works like reverse proxy
    - Proxies protect clients; WAFs protect servers
    - Inbound traffic protection
    - Outbound traffic protection (data leakage)
    - Blocklist WAF: negative security model
    - Allowlist WAF: positive security model; most WAFs hybrid
    - Network-based WAF: hardware, costly, low latency
    - Host-based WAF: co-located, scalable, costly maintenance
    - Cloud-based WAF: minimal effort, less visibility
    - WAF detects XSS, CSRF, L7 DDoS, injection, broken authentication
    - NGFW works at layers 3-4; WAF at layer 7
- Examples of firewall implementations
  - Screened-host firewall: packet-filtering router plus bastion host
  - Dual-homed firewall: two or more network interfaces
  - DMZ (screened-subnet) firewall: two routers plus bastion host
  - DMZ: intruder must penetrate three devices; hides private addresses
- Firewall issues
  - False sense of security; insider threats
  - Modems bypass firewalls
  - Misconfigured firewalls
  - Screening router misunderstood as firewall
  - Irregular monitoring
  - Policies not maintained
  - Network-layer firewalls miss SQL injection and buffer overflow
- Firewall platforms
  - Hardware: fast, less flexible
  - Software: flexible, slower, more overhead
  - Appliances preferred; hardened OS, faster recovery
- Firewall cannot identify repeated attacks: add an IDS inside the network behind it 📓⭐
### 5.4.13 Unified Threat Management (UTM)
- Multiple security features in single device
- UTM components
  - Antivirus
  - Antimalware (heuristics)
  - Sandboxing
  - Firewall
  - IDS/IPS
  - VPN
  - DLP
  - Web filtering
  - Content filtering, email and web filtering, anti-spam
- Benefits of using a UTM
  - Improves security flexibility
  - Promotes security adaptability
  - Enhances security visibility
  - Reduces costs
  - Increases security risk awareness (APT protection)
  - Encourages faster security solutions
  - Reduces security complexity
  - Simplifies monitoring and compliance
### 5.4.14 Network segmentation
- Methods, benefits, best practices
- Splits network into zones with own security requirements
- Segmentation: physical, hardware-based, north-south traffic
- Micro-segmentation: virtual, software-based, east-west traffic, per device
- Methods
  - VLAN segmentation: complex, needs re-architecting
  - Firewall segmentation
  - SDN segmentation: complex to manage
  - Host-based segmentation: agents report to central dashboard
- Benefits
  - Improves operational performance
  - Limits attack damage
  - Protects vulnerable devices
  - Improves compliance: smaller scope
  - Enhances security: defense-in-depth, hinders lateral movement
  - Improves network monitoring
- Best practices
  - Avoid under or over segmentation
  - Regular network audits
  - Control third-party access with separate portals
  - Combine similar network resources
  - Define access rights
  - Implement POLP
### 5.4.15 Endpoint security
- Endpoint: any device connecting to the network
- Examples: ATMs, IoT devices, industrial machines, laptops, medical devices, phones, printers, servers
- Benefits
  - Keeps connected devices secure
  - Promotes data security
  - Facilitates secure remote working
- Endpoint Detection and Response (EDR)
  - Continuous monitoring and automatic response
  - Component: endpoint data collection agents
  - Component: automated response
  - Component: analysis and forensics
  - Advantages: monitoring, database security, fast access, centralized visibility
  - Advantages: application control, malware detection
  - Deployment: on-location, cloud, hybrid
  - Features: antimalware, ML for zero-day, web security, DLP, firewall, email gateway
- Extended Detection and Response (XDR)
  - Broader than EDR: endpoints, cloud, email, networks
  - Part: data analysis
  - Part: detection
  - Part: response
  - Benefits: granular visibility, prioritization (MITRE ATT&CK), speed
  - Benefits: operational efficiency, sophisticated responses, prevention, control, fewer false positives
