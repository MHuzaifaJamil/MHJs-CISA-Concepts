# 5.12 Security Testing Tools and Techniques

> **Markers:** 📓 = in my Google Doc notes · ⭐ = frequently tested · ➕ = not in the review manual, verify · unmarked = gap to study. Numbering follows the ISACA CISA Review Manual 28th Ed.

### 5.12.1 Objectives of security testing
- Identification of assets
- Identification of threats and vulnerabilities
- Identification of risk
- Performance of remediation
- Evaluation of strength of assets and controls
- Adherence to security principles
### 5.12.2 Security assessments and security audits
- Security assessment: identify, evaluate, prioritize vulnerabilities and threats
- Assessment objectives: asset value, criticality, probability and impact, cost balance
- Security audit: review practices against published standard
- Security audit measures compliance (PCI DSS, ISO/IEC 27002, HIPAA)
### 5.12.3 Vulnerability assessments
- Also called vulnerability scanning
- Goals
  - Evaluate security posture
  - Identify and prioritize vulnerabilities
  - Assess reaction to attacks
  - Learn current vulnerabilities
  - Identify exploitation paths
  - Decide on controls
### 5.12.4 Penetration tests
- Phases of penetration testing
  - Planning: rules of engagement, management approval, goals, tools
  - Reconnaissance/discovery: network mapping, DNS interrogation, WHOIS
  - Reconnaissance: social media, host, service, OS detection
  - Reconnaissance: website mapping, vulnerability classification
  - Attack: directory browsing, injection, authentication circumvention
  - Attack: privilege escalation
  - Attack: information gathering from inside
  - Attack: installation of further attack tools
  - Reporting: simultaneous with all phases; risk rating and mitigation
- Manual vs automated penetration testing
  - Manual: comprehensive, finds hidden flaws, slow
  - Automated: fast, fixed predefined tests, needs manual analysis
- Scope items: IP ranges, restricted hosts, techniques, timing, source IPs, contact, NDA
- Types of penetration tests
  - External testing
  - Internal testing
  - Blind testing
  - Double blind testing: tests incident response
  - Targeted testing
- Risks of penetration testing
  - Does not find all vulnerabilities
  - Miscommunication
  - Unplanned escalation
  - Sensitive information disclosure
  - Unqualified testers
- Vulnerability assessments vs penetration testing
  - VA: broad, automated, frequent, known vulnerabilities
  - Pen test: deep, experienced testers, exploits, less frequent
  - VA should precede pen test
- Penetration testing vs ethical hacking
  - Ethical hacking broader, continuous, in-depth
  - Pen test scoped, once-off, report-focused
  - Ethical hackers assist client security teams
- Management authorization comes first, to prevent legal liability 📓⭐
- Black box test: management awareness, scope defined 📓
### 5.12.5 Threat readiness / information security teams
- Blue team: detect and mitigate attacks; SIEM and EDR
- Red team: test resilience; simulation; stealthy tools
- Purple team: improves security posture efficiently
### 5.12.6 Security testing techniques
- Static application security testing (SAST): white box, source code
- Dynamic application security testing (DAST): black box, running application
- Interactive application security testing (IAST): grey box
- Mobile application security testing (MAST)
- Software composition analysis (SCA): open-source components
### 5.12.7 Security Operations Center (SOC)
- Team monitoring entire IT infrastructure in real time
- Common activities
  - Asset inventory management
  - Security research
  - Events monitoring
  - Investigating and triaging potential incidents
  - Security infrastructure management
  - Information security testing
  - Patch management
  - Incident response
  - Post-mortem and refinement
- Full network assessment reviews
  - Review security policy and procedures
  - Evaluate network and firewall configuration
  - Logical access controls support SoD
  - Segmentation by trust level
  - IDS, filtering, encryption, strong authentication
  - Firewall configuration and proxy servers
  - Virus scanning and periodic penetration testing
  - Audit logging with SIEM
  - Track vulnerabilities via CERT and NVD
- SOC log timestamp drift hurts incident timelines 📓
### 5.12.8 Security testing audit procedures
- Terminal identification
  - Inventory terminals against network diagram
- Terminal cards and keys
  - Attempt access beyond authorization
  - Check follow-up on violations
- Logon IDs and passwords
  - Discreetly guess sample passwords
  - Look for passwords taped to terminals; check wastebaskets
  - Attempt to view internal password table
  - Review logs for clear passwords
  - Review access authorization documents
  - Test periodic change, inactive ID removal
  - Test password syntax, automatic logoff
  - Test lockout after failed attempts and reactivation process
  - Test password masking
- Controls over production resources
  - Strong control over utilities, job control libraries, parameters
  - Need-to-know access
- Logging and reporting of computer access violations
  - Attempt unauthorized access; verify reports
- Follow-up access violations
  - Check evidence of investigation
- Bypassing security and compensating controls
  - Bypass label processing (BLP)
  - System exits
  - Special system logon IDs
  - Log and investigate use; deactivate unnecessary features
