# 5.5 Data Loss Prevention (DLP)

> **Markers:** 📓 = in my Google Doc notes · ⭐ = frequently tested · ➕ = not in the review manual, verify · unmarked = gap to study. Numbering follows the ISACA CISA Review Manual 28th Ed.

- DLP: tools and processes preventing loss or misuse of sensitive data
- DLP classifies data, identifies policy violations, enforces remediation
- Consequences of data loss
  - Reduced productivity
  - Increased recovery costs
  - Legal exposure
  - Loss of customer trust and revenue
  - Risk of business closure
### 5.5.1 Types of DLP
- Network-based DLP
  - Scans outgoing data using deep packet inspection (DPI)
  - Alerts, quarantines or encrypts in real time
- Endpoint-based DLP
  - Scans files on system and sent to external devices (printers, flash drives)
  - Uses centrally managed agent
- Cloud DLP
  - Monitors cloud-stored data with predefined data types
  - Can remove sensitive email attachment
### 5.5.2 Data loss risk
- Consequences: corruption, destruction, confidential exposure, IP theft
- Technology causes
  - Loss or theft of devices
  - Unencrypted data storage
  - Software vulnerabilities and unpatched systems
  - Unsecure remote access tools
  - Insecure communication platforms and transmission links
  - Inappropriate access rights
  - Poor system programming or design
  - Production data in development environment
- Process causes
  - Poor data governance oversight
  - No data retention policy
  - No risk assessments
  - Unencrypted data kept or transmitted
  - Not enforcing POLP and need to know
  - Poor incident response
  - Software misconfigurations
  - Failure to close expired accounts
- People causes
  - Negligence and lack of training
  - Accidental file deletion
  - Emailing sensitive data unencrypted
  - Sharing work devices and passwords
  - Insider threats: data theft, sabotage, fraud
  - Blackmail via social engineering
  - Copying data to remote systems
- Threat actors: malware, software corruption, sabotage
- Natural disasters: fires, earthquakes, spills, power outages, temperature extremes
- DLP use cases
  - Compliance
  - Intellectual property protection
  - Data visibility
  - Pervasiveness
  - Frequent data breaches
  - Value of stolen data
### 5.5.3 DLP solutions and data states
- Data at rest, in transit, in use
- Data at rest: crawlers log onto systems and search for sensitive data
- Data in transit: network appliances capture packets, reassemble files, apply DPI
- Data in transit: alert, block, quarantine or encrypt
- Data in use: agent monitors copy, print, cut and paste at workstations
### 5.5.4 DLP controls
- Governance controls
  - DLP policy, procedures, guidelines
  - Classify data and assign sensitivity
  - Regular data loss risk assessment
  - Standardize endpoints
  - Document data loss incidents
  - Periodic compliance audit
- People controls
  - Do not leave sensitive data exposed
  - Prohibit copying to removable media
  - Read-only access to sensitive information
  - Data protection clauses in contracts
  - Owner authorization before exporting data
  - Train employees
- DLP deployment controls
  - Risk-based deployment, tune policies, test
  - Encrypt data in transit and at rest
- IT controls
  - Monitor sensitive data channels
  - Prohibit unauthorized devices
  - Block files with PII
  - Removable storage read-only
  - Multilayered authorization
  - Encrypt backups
  - Firewall and antivirus
- Procurement controls
  - Check compatibility with data formats
  - Real-time violation reports
### 5.5.5 DLP content analysis methods
- Regular expression matching: first filter, high false positives without checksum
- Structured fingerprinting (exact data matching, EDM): databases, directory services
- Exact file matching (EFM): file hash comparison, low false positives
- Indexed document matching (IDM): unstructured data, detects derived content
- Lexicon matching (conceptual analysis): dictionary terms and rules
- Statistical analysis: ML, Bayesian; needs large data; false positives and negatives
- Categorization: prebuilt categories such as credit card data
### 5.5.6 DLP deployment best practices
- DLP policy creation
- Define business and security requirements
- Employee involvement
- Senior management support
- Deployment mode
  - Passive (monitoring) mode: no blocking
  - Active mode: blocks leakage, informs administrator
- Incorporate strong encryption
- Address insider threats
- Data classification: start with most sensitive
- Risk assessment: data in use on endpoints highest risk
- Control documentation
- Training and development
- Workflow management: incident routing, directory integration, backup
- Audit infrastructure
### 5.5.7 DLP risk, limitations and considerations
- Improperly tuned network DLP modules
  - Tune in monitor-only mode first
  - Provide access path if critical content blocked off-hours
- Excessive reporting and false positives
  - Avoid black-box templates; roll out in phases
- Encryption limits inspection
- Graphics: DLP cannot interpret image content
  - Can identify file types, source, destination
