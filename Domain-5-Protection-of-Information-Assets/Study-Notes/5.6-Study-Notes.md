## 5.6 Overview of encryption

- Definition: encryption turns readable plaintext into unreadable ciphertext using a key.
- Definition: decryption is the reverse process, turning ciphertext back into plaintext.
- Use: protect data in transit from interception and manipulation.
- Use: protect stored information from unauthorized viewing and change.
- Use: deter and detect accidental or intentional alteration of data.
- Use: verify authenticity of a transaction or document.
- Audit impact: encryption cannot prevent loss or modification of data.
- Audit impact: key protection is the paramount concern.
- Audit impact: misuse or misconfiguration can silently undermine protection management believes exists.
- Audit impact: encryption is subject to national laws and regulations.
- Example: a laptop with encrypted disk is useless to a thief without the key.
- Exam traps
  - Encryption is a form of access control, not a guarantee of availability.
  - Strong algorithm with poorly protected keys is still a weak control.

## 5.6.1 Elements of encryption systems

- Definition: encryption algorithm is the math function that encrypts and decrypts data.
- Definition: encryption key is the secret input making each encryption unique.
- Use: wrong key decrypts the message into unreadable output.
- Definition: key length is the predetermined size of the key, in bits.
- Audit impact: longer keys resist brute force better.
- Audit impact: search time grows exponentially with key length.
- Definition: brute force attack tries every possible key until ciphertext decrypts sensibly.
- Definition: cryptanalysis is the science of finding weaknesses in algorithms.
- Definition: known plaintext attack uses matching plaintext and ciphertext samples to discard many keys.
- Audit impact: a vulnerable algorithm lets attackers shrink the key search.
- Definition: key randomness is how unpredictable the key generation process is.
- Audit impact: common words or phrases shrink the key space.
- Audit impact: a 128-bit algorithm is weakened by non-random password-based keys.
- Audit impact: enforce password syntax rules and prohibit easily guessed passwords.
- Definition: symmetric key system uses one secret key for both encryption and decryption.
- Use: the key is bidirectional and must be shared out of band.
- Definition: asymmetric key system uses a complementary public and private key pair.
- Use: public key is disclosed; private key stays with the owner.
- Audit impact: parties need not trust each other to keep a shared secret.
- Definition: hash function turns text of any length into a fixed-length digest.
- Use: augments encryption with integrity and authenticity properties.
- Audit impact: hash must be one-way; reversing a hash must be hard.
- Audit impact: a single changed bit in the message changes the hash.
- Definition: digest length depends on algorithm.
- Example: MD5 gives 128 bits, SHA-1 160 bits, SHA-512 512 bits.
- Audit impact: industry is moving from MD5 and SHA-1 to SHA-2.
- Audit impact: SHA-3 was announced by NIST in case SHA-2 is broken.
- ⚠ Check: manual says specific digest algorithms are not tested; know how signatures work.
- Encryption versus hashing
  - Encryption is two-way, variable length, and uses symmetric or asymmetric keys.
  - Hashing is one-way, fixed length, and uses no keys.
  - Encryption goal: data security in transit and at rest.
  - Hashing goal: data verification and authentication.
  - Encryption examples: AES, RC4, DES, RSA.
  - Hashing examples: SHA-1, SHA-2, MD5.
  - Encryption transforms data into ciphertext; hashing leaves the original data intact.
- Definition: salt is extra input attached to a password before hashing.
- Use: defends against dictionary attacks and rainbow table attacks.
- Definition: message integrity check compares the sender's digest with the receiver's recomputed digest.
- Use: receiver hashes the received message independently, then compares both digests.
- Audit impact: mismatch means the message was altered in transit.
- Exam traps
  - Hashing cannot be reversed, so it is not encryption.
  - Hash alone proves integrity, not who sent the message.
  - Longer key beats weaker algorithm only if keys are truly random.

## 5.6.2 Link encryption vs end-to-end encryption

- Definition: link encryption (online encryption) encrypts all traffic over one communication channel.
- Use: covers user data plus headers, trailers, addresses, and routing data.
- Use: protects against packet sniffing and eavesdropping.
- Audit impact: operates at the data link and physical layers.
- Audit impact: packets are decrypted and re-encrypted at every hop.
- Audit impact: intermediate devices see the destination, creating many vulnerabilities.
- Audit impact: only data link control synchronization messages stay unencrypted.
- Advantage: simple, because users play no role in initiating it.
- Disadvantage: every hop needs a key, so key changes touch every device.
- Definition: end-to-end encryption (E2EE) keeps the message encrypted from origin to destination.
- Use: only the two communicating parties can read the message.
- Audit impact: intermediaries cannot decrypt; viewed as more secure than link encryption.
- Audit impact: headers, addresses, and routing information stay unencrypted and exposed.
- Advantage: no encryption work at each hop.
- Advantage: user decides which message types to encrypt.
- Example: WhatsApp messaging uses end-to-end encryption.
- Exam traps
  - Link encryption hides routing data; E2EE leaves routing data readable.
  - User involvement signals E2EE; transparent to users signals link encryption.
  - Hop-by-hop decryption is the weakness of link encryption.

## 5.6.3 Symmetric key cryptographic systems

- Definition: same secret key encrypts plaintext and decrypts ciphertext.
- Definition: DES is the older standard, now withdrawn.
- Definition: 3DES (Triple DES) extended DES while keeping backward compatibility.
- Definition: AES replaced DES in 2001, with 128 to 256-bit keys.
- Definition: RC4 is a stream cipher often used in SSL/TLS sessions.
- Advantage: keys are shorter and easily remembered.
- Advantage: less complex and less processing than asymmetric schemes.
- Use: ideal for bulk data encryption.
- Disadvantage: key distribution is hard, especially with unknown, untrusted e-commerce customers.
- Disadvantage: shared secret means it cannot sign documents.
- Audit impact: key management is typically difficult with symmetric encryption.
- Exam traps
  - Symmetric cannot give nonrepudiation because two parties hold the same key.
  - Bulk data points to symmetric; key distribution problem points to asymmetric.

## 5.6.4 Public (asymmetric) key cryptographic systems

- Definition: two inversely related keys, based on integer factorization, work as a pair.
- Use: public key encrypts; matching private key decrypts.
- Audit impact: private key never has to be shared with the other party.
- Audit impact: one key pair works in one direction only.
- Audit impact: two-way communication needs two key pairs.
- Use: built mainly to solve the key distribution problem.
- Audit impact: exchanged keys are public, so distribution needs no confidentiality.
- Audit impact: key management is simpler with asymmetric encryption.
- Definition: RSA is the first practical public key system (Rivest, Shamir, Adleman).
- Audit impact: RSA keys run 1024 to 4096 bits.
- Audit impact: drawback is key length and heavy computation.
- Calculation: key count for N communicating parties.
  - Formula: asymmetric needs N key pairs, so 2N keys.
  - Formula: symmetric needs one key per pair of parties, N(N-1)/2.
  - Step: take N = 10 parties.
  - Step: asymmetric gives 2 x 10 = 20 keys (10 pairs).
  - Step: symmetric gives 10 x 9 / 2 = 45 keys.
  - Step: at N = 100, asymmetric is 200 keys.
  - Step: at N = 100, symmetric is 100 x 99 / 2 = 4,950.
  - Verification: counting pairs of 10 parties by hand gives 45, matching the formula.
- ⚠ Check: manual says symmetric needs roughly N squared keys; exact count is N(N-1)/2.
- Exam traps
  - Asymmetric scales better for many parties; symmetric is faster for bulk data.
  - Public key encrypts for confidentiality; private key stays secret.

## 5.6.5 Elliptic curve cryptography

- Definition: ECC is a public-key system based on elliptic curves over finite fields.
- Use: supports encryption, signatures, and key exchange like other asymmetric systems.
- Audit impact: gives equal security with considerably smaller keys than RSA.
- Audit impact: fast key generation, fast key agreement, fast signatures.
- Audit impact: more bandwidth savings than RSA.
- Audit impact: RSA relies on prime factorization; ECC relies on elliptic curve theory.
- Audit impact: considered a natural modern successor to RSA.
- Example: mobile devices favor ECC because small keys save power and bandwidth.
- ➕ Example: mobile suitability is general industry knowledge, not stated in the manual.
- Exam traps
  - Smaller key does not mean weaker security here.
  - ECC is asymmetric, not symmetric.

## 5.6.6 Quantum cryptography

- Definition: cryptography relying on quantum mechanics, using photons over fiber optic cables.
- Definition: quantum key distribution (QKD) securely shares an encryption key between two parties.
- Use: parties detect eavesdropping because observing a quantum state changes it.
- Audit impact: tampering cannot happen without the communicating parties noticing.
- Benefit: security rests on laws of physics.
- Benefit: protects against eavesdropping through detectable state changes.
- Benefit: offers a variety of protocols, combinable with usual encryption.
- Benefit: simple to operate despite high initial outlay.
- Limitation: photon polarization may change in transit, causing channel errors.
- Limitation: range is generally about 500 km on guided media.
- Limitation: costly, often needing separate repeaters and fiber infrastructure.
- Limitation: one dedicated channel per destination; no multiplexing.
- ⚠ Check: manual notes Terra Quantum can exceed 500 km; treat limit as general.
- Exam traps
  - Quantum cryptography detects eavesdropping; it does not make interception impossible.
  - Cost and range, not weak security, are its limits.

## 5.6.7 Homomorphic encryption

- Definition: encryption allowing mathematical operations on data while it stays encrypted.
- Use: outsource data processing without third parties seeing the plaintext.
- Audit impact: without the decryption key, original data is inaccessible.
- Benefit: supply chain security, since a third-party breach exposes only ciphertext.
- Benefit: cloud data security, allowing calculation and search on ciphered data.
- Benefit: data security, such as private summing of values in elections.
- Benefit: regulatory compliance, such as GDPR, by decrypting only in compliant locations.
- Benefit: data analytics without viewing the original data.
- Benefit: privacy when sharing private data with customers.
- Definition: partially homomorphic allows infinite operations of one type only.
- Example: RSA is partially homomorphic; auditors should note this.
- Definition: somewhat homomorphic allows a finite number of any operation.
- Example: up to six operations work; a seventh gives an invalid result.
- Definition: fully homomorphic allows infinite additions and multiplications with valid results.
- Audit impact: fully homomorphic is the desired end goal.
- Challenge: inefficiency, because full homomorphism needs slow algorithms.
- Challenge: high storage requirements from heavy processing workloads.
- Challenge: reduced performance; still much slower than plaintext operations.
- Challenge: inability to scale with very many users.
- Challenge: large, complex algorithms with big computation overhead.
- Exam traps
  - Homomorphic encryption lets processing happen without decrypting; its cost is performance.
  - Partial means one operation type, unlimited; somewhat means limited count, any type.

## 5.6.8 Digital signatures ⭐

- Definition: private key encrypts a message digest; the public key verifies it.
- Use: authenticates origin of a message.
- Audit impact: algorithm works with the key roles reversed from normal encryption.
- Definition: pre-hash is the digest derived from the document before signing.
- Definition: post-hash is the digest the receiver computes from the received document.
- Use: signing the digest avoids heavy processing of the whole document.
- Step: sender hashes document, then encrypts digest with private key.
- Step: receiver decrypts signature with sender's public key to get pre-hash.
- Step: receiver hashes the document and compares post-hash to pre-hash.
- Audit impact: a match shows the document was signed by the key owner.
- Guarantee: data integrity, because any change alters the hash.
- Guarantee: authentication, because only the claimed sender holds the private key.
- Guarantee: nonrepudiation, because the sender cannot later deny generating it. 📓⭐
- Definition: replay attack resends an intercepted signed document to the recipient.
- Use: signed timestamp or counter prevents replay.
- Audit impact: a valid signature does not prove the owner just sent it.
- Exam traps
  - Digital signature gives integrity, authentication, nonrepudiation; it does not give confidentiality.
  - Signing uses sender's private key; verifying uses sender's public key.
  - Nonrepudiation requires asymmetric keys; symmetric keys cannot provide it.

## 5.6.9 Digital envelope

- Definition: electronic container protecting a message using symmetric and public-key encryption.
- Step: message is encrypted with a symmetric key.
- Step: that symmetric key is encrypted with the receiver's public key.
- Use: receiver uses private key to recover the symmetric key, then reads the message.
- Audit impact: combines symmetric speed with asymmetric key distribution convenience.
- Example: Pretty Good Privacy (PGP) is a typical digital envelope.
- Exam traps
  - Envelope encrypts the key asymmetrically, never the bulk message.

## 5.6.10 Applications of cryptographic systems

- Definition: combined scheme encrypts data symmetrically, then protects the key asymmetrically.
- Use: gives symmetric speed and asymmetric ease of key distribution.
- Audit impact: a fresh secret key per limited data amount limits damage if cracked.
- Use: the combined scheme underlies SSL/TLS and S/MIME.

### Transport Layer Security (TLS)

- Definition: protocol giving secure internet communication, privacy, and endpoint authentication.
- Use: prevents eavesdropping, tampering, and message forgery between client and server.
- Phase one: peers negotiate supported algorithms.
- Phase two: public-key key exchange and certificate-based authentication.
- Phase three: symmetric cipher encrypts the traffic.
- Public-key choices: RSA, Diffie-Hellman, DSA, Fortezza.
- Symmetric choices: RC4, IDEA, Triple DES, AES.
- Hash choices: SHA-1 or SHA-2.
- Audit impact: runs above TCP and secures application protocols.
- Example: HTTPS is TLS used with HTTP.
- Audit impact: B2B authenticates client and server; B2C authenticates the server only.
- Definition: Handshake Protocol negotiates and establishes the connection before data is sent.
- Definition: Record Protocol encrypts and authenticates packets, relying on the handshake.
- Audit impact: TLS replaced SSL after a significant 2014 vulnerability.
- Audit impact: SSL and TLS are incompatible, but "SSL" is often used loosely.
- Audit impact: check whether an SSL reference is real or means TLS.
- ⚠ Check: manual lists RC4, SHA-1, Fortezza; treat as dated ➕.

### IP Security (IPsec)

- Definition: network-layer protocol securing communication between hosts, subnets, or both.
- Use: establishes VPNs through transport and tunnel modes.
- Definition: transport mode encrypts the ESP payload, which is the packet data.
- Definition: tunnel mode encrypts the ESP payload and its header.
- Definition: authentication header (AH) is added to achieve nonrepudiation.
- Definition: encapsulating security payload (ESP) carries the encrypted data portion.
- ⚠ Check: AH is normally described as authentication and integrity, not true nonrepudiation ➕.
- Step: sender checks its security policy to see if IPsec is required.
- Step: both systems negotiate encryption, authentication, and security association parameters.
- Step: systems exchange encrypted data and validate the trusted source.
- Step: session ends on completion or timeout.

### Security association (SA)

- Definition: one-way connection negotiating ESP or AH parameters.
- Audit impact: contains key material, usable algorithms, endpoint identities, and other parameters.
- Definition: security parameter index (SPI) is a 32-bit field identifying the SA.
- Use: lets the sending host reference parameters to apply on the receiving host.
- Definition: ISAKMP is the framework managing negotiation and communication of SAs.
- Definition: IKE handles key management automatically using asymmetric cryptography.
- Exam traps
  - Transport mode protects data only; tunnel mode also hides the original header.
  - IPsec works at network layer; SSH and TLS work above it.

## 5.6.11 Kerberos

- Definition: ticket authentication mechanism using a trusted third party.
- Use: single sign-on (SSO) in a distributed computing environment.
- Audit impact: Kerberos 5 uses AES symmetric encryption.
- Audit impact: protects against eavesdropping and replay attacks.
- Component: Key Distribution Center (KDC) is the trusted third party holding all secret keys.
- Component: Ticket-Granting Server (TGS) validates ticket use for a specified purpose.
- Component: Authentication Server (AS) hosts the TGS and checks ticket authenticity and timeliness.
- Component: Ticket-Granting Ticket (TGT) proves the user authenticated through the KDC.
- Component: Service Ticket (ST) is encrypted proof of authorization to access an object.
- Logon step: user logs on with username and password.
- Logon step: client encrypts the username and sends it to the KDC.
- Logon step: KDC verifies credentials in its directory service.
- Logon step: KDC generates a symmetric key and an encrypted TGT.
- Logon step: KDC encrypts the symmetric key with the user's password hash.
- Logon step: client decrypts the key using its own password hash.
- Logon step: client sends the TGT to the TGS to request a service ticket.
- Audit impact: the password is never sent over the network.
- Risk: KDC is a single point of failure.
- Risk: KDC compromise exposes the secret key of every system.
- Risk: KDC offline means no subject authentication takes place.
- Risk: strict time requirements; wrong clock invalidates the TGT.
- Risk: invalid TGT means no new tickets and denied access.
- Exam traps
  - Kerberos weakness is KDC concentration and time sync, not password transmission.
  - Clock drift causes access denial, not data corruption.

## 5.6.12 Secure Shell (SSH)

- Definition: client-server program giving encrypted command-line sessions for remote logon.
- Use: replaced Telnet, which sent passwords in clear text.
- Audit impact: encrypts authentication, commands, output, and file transfers.
- Audit impact: implemented at the application layer, unlike network-layer IPsec.
- Use: remote logon for support and maintenance.
- Use: file transfer between computers.
- Use: remote command execution.
- Use: offering support and updates.
- Best practice: centralize key management to avoid key sprawl.
- Audit impact: key sprawl, keys stored everywhere, enlarges the attack surface.
- Best practice: change the default SSH port, a defense-in-depth step.
- Best practice: disable SSH root login.
- Best practice: key attribution, tying keys to individuals, not shared accounts.
- Audit impact: attribution provides a usable audit trail.
- Best practice: key rotation, forcing regular key regeneration and no password reuse.
- Best practice: continuous audits recording and verifying privileged SSH sessions.
- Best practice: firewall allowlisting of sources, rate-based blocking, and port knocking.
- ⚠ Check: changing the default port is obscurity, useful but weak alone ➕.
- Exam traps
  - Shared SSH accounts destroy accountability; attribute keys to individuals.
  - SSH replaces Telnet because Telnet exposes credentials.

## 5.6.13 DNS Security Extensions (DNSSEC)

- Definition: cryptographic technology adding digital signatures to DNS records.
- Use: DNS itself has no built-in security measures.
- Audit impact: provides origin authentication, authenticated denial of existence, and data integrity.
- Audit impact: responses failing validation are discarded.
- Stage: signing, where records are signed with the private key.
- Stage: validation, where resolvers check signatures using PKI public keys.
- Definition: DNS cache poisoning floods a resolver with false data that enters its cache.
- Audit impact: DNSSEC prevents cache poisoning by rejecting unsigned or forged answers.
- Definition: DNS false zones are phony results for nonexistent zones, exploiting gaps.
- Audit impact: authenticated denial of existence closes those gaps.
- Vulnerability: DDoS amplification, since responses grow larger.
- Vulnerability: more query responses, with extra fields and cryptographic data.
- Vulnerability: UDP reliance is faster but riskier, with no handshake.
- Audit impact: UDP traffic can be easily intercepted.
- ⚠ Check: manual blames UDP; DNS generally uses UDP with TCP fallback ➕.
- Exam traps
  - DNSSEC proves authenticity and integrity; it does not encrypt DNS queries.
  - DNSSEC can increase DDoS amplification risk.

## 5.6.14 Email security

- Definition: email security protects confidentiality, integrity, and availability of email.
- Audit impact: email is often the primary attack vector for other attacks.

### Common email attacks and techniques

- Definition: bombing is repeatedly sending an identical message to one address.
- Definition: spamming is sending unsolicited bulk email, a business and productivity risk.
- Audit impact: responding to spam validates the recipient's address.
- Audit impact: spam may be combined with spoofing to hide the sender.
- Use: spam is managed with SPF, Bayesian filtering, and grey listing.
- ⚠ Check: manual writes "Sender Permitted Framework"; standard name is Sender Policy Framework ➕.
- Definition: spoofing is email that appears from one source but comes from another.
- Example: fake administrator email demanding a password change or threatening account suspension.
- Definition: business email compromise (BEC) targets staff who authorize financial transactions.
- Audit impact: attackers research executives, vendors, and partners to appear credible.
- Audit impact: train staff to spot fake domains and vendor impersonation.

### Email security technologies (Figure 5.35)

- Definition: S/MIME gives email authentication and confidentiality via public keys and signatures.
- Audit impact: uses X.509 certificates to authenticate sender and receiver.
- Audit impact: provides integrity, sender authentication, confidentiality, and nonrepudiation.
- Definition: MIME Object Security Services (MOSS) signs MIME objects with multi-party frameworks.
- Audit impact: MOSS has never been widely used.
- Definition: Privacy Enhanced Mail (PEM) uses RSA and DES, based on X.509.
- Audit impact: provides authentication, integrity, confidentiality, and nonrepudiation.
- Definition: DomainKeys Identified Mail (DKIM) signs mail to show the domain owner authorized it.
- Audit impact: primary purpose is detecting forged sender addresses.
- Definition: Pretty Good Privacy (PGP) is a public-private key system for files and email.
- Audit impact: provides authentication, integrity, privacy, and nonrepudiation; open source.

### Email security controls

- Definition: secure email gateway (SEG) filters unwanted email per administrator settings.
- Audit impact: deployable on-premises or in the cloud; adds to layered defense.
- Definition: email attachment control (EAC) lets users see file types before opening.
- Audit impact: reduces risk from malicious links and attachments.
- Definition: spam filters send detected spam to a junk folder by pattern matching.
- Definition: email encryption protects intercepted email from being read without the key.
- Audit impact: reduces data leakage and regulatory or policy violations.
- Definition: antivirus protection screens emails and attachments for viruses.
- Exam traps
  - Digital signature on email gives sender proof; encryption gives confidentiality.
  - Training addresses BEC better than technical filters alone.

## 5.6.15 Encryption audit procedures

- Objective: confirm controls exist to manage overall data encryption processes.
- Policy: verify written encryption policies and procedures exist.
- Policy: confirm a data classification system is present.
- Policy: confirm encryption risk assessments occur regularly.
- Policy: verify no duplicated encryption.
- Policy: verify dual control and separation of duties support encryption.
- Policy: verify compliance with data protection rules and regulations.
- Policy: verify an audit system exists for encryption.
- Design: algorithm selection is effective, efficient, and documented as adequately protective.
- Design: processes minimize effect on interfacing and other systems.
- Design: respected standards, such as TLS, are applied.
- Design: system is compatible with applications.
- Design: key length, composition, and management follow policy.
- Design: assess difficulty of key generation and modification.
- Key management: changes to the cryptographic system are controlled.
- Key management: only authorized individuals make changes or updates.
- Key management: key transmission follows a written procedure.
- Key management: key creation, rotation, and destruction follow policy or industry standards.
- Key management: users and operators do not handle keys.
- Digital signatures: private keys are never backed up, since backups increase exposure.
- Digital signatures: use different key pairs for encryption and signatures.
- Algorithms: management considered the need for complex mathematical equations.
- Algorithms: cost of deciphering should not exceed the information's value.
- ⚠ Check: manual wording reversed; attacker's deciphering cost should exceed the information's value.
- Control: full disk encryption protects lost or stolen devices. 📓⭐
- Rule: if the device is physically lost, encryption is the answer. 📓
- Exam traps
  - Backing up signing private keys looks safe but increases exposure.
  - Users handling keys breaks separation of duties.
  - For data on a stolen laptop, choose disk encryption, not access logs.
  - For data crossing untrusted networks, choose VPN or transit encryption. 📓

## Takeaway

- Protect keys first; encryption cannot prevent data loss or modification.
- Symmetric is fast for bulk data; asymmetric solves key distribution.
- Digital signatures give integrity, authentication, and nonrepudiation, not confidentiality.
- Digital envelope and TLS combine both key types.
- Kerberos risks are KDC single point of failure and clock sync.
- Audit focus: policy, algorithm design, key lifecycle, and unbacked private signing keys.
