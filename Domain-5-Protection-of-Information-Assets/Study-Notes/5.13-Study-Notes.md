# 5.13 Security Monitoring Logs, Tools and Techniques - Study Notes

Scope: 5.13-Security-Monitoring-Logs-Tools-and-Techniques.md (CISA Review Manual 28th Ed., sections 5.13.1 to 5.13.7).

## 5.13.1 Information security monitoring

- Term: information security monitoring
  - Definition: reviewing information to spot malicious users, intrusion attempts and system failures.
  - Use: reconstruct events, give evidence for prosecution, support forensic reports.
  - Audit impact: no monitoring means no detection, no accountability, no usable evidence.
- Term: log analysis
  - Definition: systematic review of logged data for trends, indications and patterns.
  - Use: detect potential security issues early.
  - Audit impact: logs that nobody reviews give no real control value.
- Benefit: enforces accountability.
  - Definition: users can be held responsible because their actions are recorded.
  - Audit impact: look for audit trails tied to unique user IDs.
- Benefit: promotes positive behavior.
  - Definition: users who know they are logged avoid circumventing controls.
  - Use: acts as a deterrent control.
- Benefit: encourages a compliance culture.
  - Definition: laws, regulations and policies often require monitoring and accountability.
- Benefit: supports investigations.
  - Definition: audit trails show conditions before, during and after an event.
  - Use: rebuild what happened, in order.
- Term: NTP (Network Time Protocol) 📓
  - Definition: a protocol that keeps clocks on all systems in sync.
  - Use: keeps timestamps consistent across the environment.
  - Audit impact: unsynchronized clocks break event sequencing and forensic timelines.
  - Example: server A logs 10:02, server B logs 10:07 for one event.
- Benefit: identifies security problems.
  - Definition: logs reveal failures, OS bugs, software errors and attacks.
  - Use: some logs capture memory contents after a crash.
- Exam traps
  - Out-of-sync timestamps harm forensic reconstruction, not storage or indexing.
  - Monitoring is detective; it does not itself stop an attack.

## 5.13.2 Intrusion Detection Systems (IDS)

- Term: IDS
  - Definition: a system that watches for suspicious activity and warns administrators.
  - Use: complements firewalls by monitoring network use anomalies.
  - Audit impact: it alerts only; someone must read and act on alerts.
  - Example: IDS flags a burst of failed logins at 3 a.m.
- IDS runs continuously in the background.
  - Use: protects against external and internal misuse.
- Term: network-based IDS (NIDS)
  - Definition: sensors on the network that watch traffic for attacks.
  - Use: raises a warning to the operator.
  - Audit impact: placement decides what the IDS can see.
- NIDS placement
  - Between Internet and firewall: sees all attack attempts, entering or not.
  - Between firewall and corporate network: sees only attacks that got through.
  - IDS complements a firewall; it never replaces it.
  - Example: a firewall cannot show repeated blocked probes; an outside IDS can.
- Internal IDS behind the firewall detects attacks that pass the perimeter. 📓
- IDS inside the boundary watches traffic crossing the perimeter. 📓
- Term: host-based IDS (HIDS)
  - Definition: software on one host watching its own OS resources.
  - Use: detects executable changes, file deletion and privileged command attempts.
  - Audit impact: catches insider and post-breach activity that network sensors miss.
- IDS components
  - Sensors: collect packets, log files and system call traces.
  - Analyzers: take sensor input and decide whether activity is intrusive.
  - Administration console: where administrators configure and manage the IDS.
  - User interface: how operators view alerts.
- IDS types
  - Signature-based: matches stored patterns of known intrusions.
  - Signature weakness: cannot detect intrusions without a matching rule.
  - Statistical-based: compares activity to a defined normal behavior profile.
  - Statistical weakness: flags many harmless events as abnormal (false positives).
  - Neural network: like statistical, but with self-learning added.
  - Combining signature and statistical models gives better protection.
- IDS features
  - Intrusion detection and evidence gathering on intrusive activity.
  - Automated response, such as ending a connection or sending an alarm.
  - Security policy, interface with system tools, policy management.
- IDS limitations: it cannot fix these weaknesses.
  - Weaknesses in policy definition.
  - Application-level vulnerabilities.
  - Back doors in applications.
  - Weaknesses in identification and authentication (I&A).
- IDS policy
  - Definition: management-defined actions staff take when an intruder is detected.
  - Terminate access: used when risk to data or systems is significant.
  - Trace access: used when risk is low or analysis and evidence are wanted.
  - Tracing finds system weaknesses and gathers evidence for court.
  - Management must predefine the action; this saves time and limits data loss.
- Exam traps
  - IDS is not a firewall substitute; the answer is "complements".
  - Best placement to see all attempts is outside the firewall.
  - Signature-only IDS misses new attacks; statistical-only produces false alarms.
  - Tracing versus terminating depends on risk, set in policy beforehand.

## 5.13.3 Intrusion Prevention Systems (IPS)

- Term: IPS
  - Definition: an IDS-like control that tries to stop attacks, not just report them.
  - Use: blocks the source address or session; may reconfigure firewalls or routers.
  - Audit impact: a misconfigured IPS can block legitimate traffic and cause outages.
- IPS needs proper tuning.
  - Thresholds set too high or too low reduce effectiveness.
- IPS can itself be abused.
  - An attacker may trigger it to make many protected hosts dysfunctional.
  - Impact is severe where service continuity is critical.
- IPS types
  - HIPS: software on clients and servers, stops attacks at device level.
  - NIPS: deployed in network infrastructure, stops threats before they reach targets.
  - WIPS: watches radio waves for rogue access points and counters them.
- IDS versus IPS
  - IDS monitors and flags; IPS accepts or rejects packets by rules.
  - IPS can do the IDS job; an IDS cannot do the IPS job.
  - IDS needs a human to respond; IPS acts proactively on its own.
  - IPS usually sits at the firewall juncture; IDS watches across the network.
  - IDS range is wider; IPS can lean on IDS to extend surveillance.
  - IPS can block zero-day threats because it does not rely only on signatures.
  - ⚠ Check: manual places IPS both "behind" and "at" the firewall.
  - ⚠ Check: manual says IDS runs inline, IPS host or inline; likely swapped.
  - ⚠ Check: zero-day blocking relies on behavior or ML models; it is not guaranteed.
- Term: honeypot
  - Definition: a decoy server that pretends to be vulnerable.
  - Use: lures attackers so their methods can be studied.
  - Audit impact: it does not protect the network; it only gathers intelligence.
  - Example: a fake database server with no real data, watched for probes.
- Honeypot types
  - High-interaction: a real environment for attackers to attack.
  - Low-interaction: emulates production and gives limited information.
- Term: honeynet
  - Definition: several linked honeypots simulating a larger network.
  - Use: investigators watch attackers using IDS, keystroke logger and a separate firewall.
  - Audit impact: collected data helps patch vulnerabilities on the live network.
- All honeypot and honeynet traffic is assumed suspicious.
  - Reason: these systems are not meant for internal use.
- Honeypot risk
  - External services may list the organization as vulnerable, hurting reputation.
  - Weigh this carefully before exposing a honeypot to the Internet.
- IDS/IPS best practices
  - Perform an asset inventory; it determines placement.
  - Establish an IDS/IPS policy and standards; update with the threat environment.
  - Set a baseline of normal network behavior.
  - Place first at the highest point of visibility, then work down.
  - Consider multiple installations to cover intra-host traffic.
  - Tune continuously: update rules as signatures and the network change.
  - Develop logging systems able to handle large data, backup and storage.
  - Deploy network-based first; host-based follows (can be concurrent).
  - Network deployment starts at the perimeter edge, then DMZ and other devices.
  - Create an incident response plan with written steps and a notification chain.
- Exam traps
  - "Stops the attack" points to IPS; "alerts only" points to IDS.
  - Honeypot is a detection and research tool, never a preventive control.
  - A baseline comes before tuning; tuning is ongoing, not one-time.

## 5.13.4 Audit logging in monitoring system access

- System access logging
  - Definition: access control software records access attempts by logon ID or terminal.
  - Use: shows suspicious activity, such as brute force on a privileged ID.
  - Audit impact: gives management a trail to monitor and investigate.
  - Keystroke logging can be turned on for users with sensitive privileges.
- Log policy issues to decide
  - What is logged.
  - Who or what can access the logs.
  - How long logs are retained.
- Access rights to system logs
  - Strictly control access for those doing logging and monitoring.
  - Security managers and system administrators get review access.
  - Staff maintaining logical access functions may not need log access.
- Integrity of audit trails
  - Intruders try to alter logs to cover their tracks.
  - Protect with digital signatures, write-once devices or a SIEM.
  - Integrity matters most when logs serve as legal evidence.
  - Legal-evidence use may need daily printing and signing; consult legal counsel.
- Confidentiality of audit trails
  - Logs may hold sensitive data, such as personal transaction details.
  - Use strong access controls and encryption.
- Term: media logging
  - Definition: recording control numbers, dates, names and signatures for media transfers.
  - Use: supports accountability for tapes and disks.
  - Audit impact: spot checks confirm items are with the named custodians.
  - Automated media-tracking systems help maintain inventories.
- Periodic review of system logs finds access-authority breaches and odd-hour access.
- Tools for audit trail analysis
  - Reason: raw audit files are huge; automated tools make review effective.
  - Audit reduction tools: pre-process logs, removing low-significance records.
  - Example: dropping records from nightly backups before review.
  - Trend/variance-detection tools: flag deviations from normal user or system behavior.
  - Example: a user normally logging in at 09:00 appears at 04:30.
  - Attack-signature-detection tools: look for event sequences matching known attacks.
  - SIEM systems: capture logs, analyze in real time, correlate and alert.
  - Some SIEMs run automated actions, such as vulnerability scans or closing ports.
- Cost considerations
  - System overhead from recording; more detail means more overhead.
  - Logging every event can slow or lock up a system.
  - Storage and processing costs for records.
  - Human and machine time for analysis; tools reduce it.
  - Simple utility-built analyzers are cheap but limited; SIEMs cost more.
  - Cost of investigating anomalies; too many alerts waste staff time.
  - Review frequency should match the sensitivity of the data protected.
  - The auditor ensures logs cannot be altered without leaving a trail.
- Violation follow-up: what the auditor looks for
  - Patterns indicating privilege abuse, such as focus on a sensitive application.
  - Unauthorized file access attempts and repeated wrong passwords.
- Violation follow-up: handling steps
  - The identifier refers the problem to the security administrator.
  - Security and management jointly judge severity; most violations are accidental.
  - Serious violations go to executive management, not straight to law enforcement.
  - Executive management decides on notifying law enforcement.
  - Reason: external involvement can cause publicity worse than the violation.
  - Have procedures to manage public relations and the press.
  - Written guidelines define violation types, levels and handling.
  - Disciplinary action is formal and consistent, and legally and ethically sound.
  - Corrective steps include reviewing access rules and removing excessive access.
- Exam traps
  - Report a serious violation to executive management; never call police first.
  - Log integrity beats log volume; unprotected logs lose evidential value.
  - Reduction tools cut noise; they do not detect attacks themselves.

## 5.13.5 Protecting log data

- Why it matters
  - Attackers who modify logs erase their trail and spoil evidence.
  - Altered logs may be inadmissible in prosecution.
  - Auditor evaluates procedures protecting logs from access and modification.
- Centralize log storage.
  - Use: a copy survives if the original is modified or corrupted.
- Implement access controls.
  - Users get no access unless needed to create entries.
  - Where needed, append-only privileges and no read access if possible.
- Restrict logging of sensitive data.
  - Do not record unneeded data, such as passwords.
- Establish log policies.
  - Mandate log backups and define retention times.
- Secure log transfer.
  - Use secure protocols such as IPsec and TLS to central servers.
- Secure storage media.
  - Keep media in secure locations with monitored access.
  - Apply environmental controls such as temperature and humidity.
- Protect archived logs.
  - Create and secure message digests; encrypt files; protect archive media.
  - Also secure log-generating processes, executables and configuration files.
- Log disposal controls.
  - Destroy media completely and permanently when logs expire.
  - Goal: avoid data remanence, which is residual recoverable data.
- Exam traps
  - Append-only is the best answer for log access; not read or edit.
  - Central copies protect availability and integrity; they do not replace access control.

## 5.13.6 Security Information and Event Management (SIEM)

- Term: SIEM
  - Definition: central software that gathers, correlates and alerts on security events.
  - Use: turns many isolated events into one relevant security incident.
  - Audit impact: only effective if sources are complete and rules are tuned.
  - Example: failed logins, a new admin account, then data transfer become one incident.
- Correlation methods
  - Rule-based: situation-specific rules define a pattern of events.
  - Statistical: algorithms compute threat levels for events on IT assets.
- SIEM combines two technologies.
  - SIM: collects log data for analysis and reporting on past events.
  - SEM: works in real time to identify and correlate events as they happen.
- Log collection methods
  - Agentless: SIEM server pulls logs by authenticating, or hosts push logs.
  - Agentless needs no special software on the log-generating host.
  - Agent-based: an installed agent filters, aggregates and normalizes logs in real time.
  - Several agents may run on one server for different log types.
- SIEM benefits
  - Enhances analytics; ML and AI help detect complex attacks.
  - Enhances regulatory compliance through centralized auditing and reporting.
  - Faster response when integrated with SOAR (security orchestration, automation and response).
  - Supports investigations by holding all log data in one place.
  - Improves threat intelligence by ingesting proprietary or open-source feeds.
  - Insight into past events: shows how and why an attack happened.
  - Real-time attack detection by comparing activity to past behavior.
  - Reduces security staffing needs through a single multi-source report.
- SIEM features
  - Policies: default rules, alerts, reports and dashboards, tunable to the organization.
  - Security knowledge base: known vulnerabilities and log message interpretation.
  - Log data management: pools logs from all sources in one place.
  - Event correlation and analytics: groups events, applies correlation rules.
  - Notifications and alerts: analysts use them to define new alert criteria.
  - Network visibility: inspects packet captures and flows to reveal exfiltration.
  - Security incident monitoring: tracks events in real time with workflow.
  - Compliance reporting: generates reports for applicable requirements.
- SIEM implementation best practices
  - Set implementation scope, based on goals, compliance and threat landscape.
  - Provide a holistic posture: predefined correlation rules across systems, networks and cloud.
  - Identify all compliance requirements and configure real-time reporting.
  - Classify all digital assets to simplify log management.
  - Fine-tune configurations to cut false positives; vendor rules are only defaults.
  - Implement an incident response plan covering SIEM alert handling.
  - Automate and integrate with AI and SOAR.
  - Assign a SIEM administrator; consider a managed security service provider (MSSP).
  - Monitor access controls: privileged access, remote logins and system failures.
  - Test the SIEM to improve alert metrics and infrastructure configuration.
- Exam traps
  - SIEM correlates; a log server merely stores. Correlation is the differentiator.
  - Untuned SIEM floods analysts with false positives, so tuning is a key control.
  - SIM is historic analysis; SEM is real time.

## 5.13.7 Security monitoring tools

- Term: security monitoring tools
  - Definition: technologies that watch, detect and analyze system and network activity.
  - Use: provide alerts, metrics, traffic analysis and visualizations.
  - Audit impact: speed up threat investigation and troubleshooting.
- Tools collect data and metrics across systems.
- Tools use threat intelligence to produce charts and graphs.
- Tools warn teams automatically so they can respond quickly.
- Exam traps
  - Tools only help if alerts are reviewed and acted on.

## Takeaway

- Place IDS outside the firewall to see all attempts.
- IDS alerts; IPS blocks; honeypots only study attackers.
- Protect logs with central, append-only, encrypted and digitally signed storage.
- Synchronize clocks with NTP so forensic timelines hold.
- SIEM value comes from correlation and tuning, not collection alone.
- Executive management, not staff, decides on notifying law enforcement.
