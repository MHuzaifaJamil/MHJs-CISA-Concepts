# 5.9 Mobile, Wireless and Internet of Things Devices

> **Markers:** 📓 = in my Google Doc notes · ⭐ = frequently tested · ➕ = not in the review manual, verify · unmarked = gap to study. Numbering follows the ISACA CISA Review Manual 28th Ed.

- Portable devices operate where physical controls are lacking
- Need encryption and strong authentication
- Some data inappropriate for storage on mobile devices
### 5.9.1 Mobile computing
- Devices moved during normal use: tablets, smartphones, laptops, USB storage, cameras
- Vulnerabilities and risk (Figure 5.48)
  - Wireless networks less secure: information interception
  - Mobility leaves enterprise boundaries: malware propagation
  - Bluetooth left on and discoverable
  - Unencrypted stored information
  - Lost or stolen devices, no backup
  - No authentication requirements
  - Unmanaged device, no mobile strategy
  - Unsigned third-party applications
### 5.9.2 Mobile device threats
- Information interception
- Malware propagation
- Lost business
- Data leakage
- Open public Wi-Fi
- Outdated devices
- Identity theft
- Drive-by downloads
### 5.9.3 Mobile device controls
- Device registration
- Physical security: cable locks, covered cameras
- Bluetooth disabled when unused
- Wi-Fi: avoid public networks
- Software updates
- Location services disabled when unneeded
- Strong lock-screen passwords, auto-lock
- Minimal applications from official stores
- Minimal data storage, regular backup
- Virus detection and control
- Compliance with enterprise standards, MFA
- Approval
- Acceptable use policy
- Due care; report loss as security breach
- Awareness training
- Network authentication, authorization and accounting
- Secure transmission via VPN
### 5.9.4 Mobile Device Management (MDM)
- Suite of tools to secure and manage devices, apps, data, access
- Objectives: security, monitoring, remote management, troubleshooting
- Basic MDM features
  - Encryption
  - Remote wiping: does not guarantee permanent removal
  - Device lockout
  - Assets management (GPS tracking)
  - Application control
  - Device troubleshooting
  - Credential management
  - Secure remote support
  - Standard mobile device applications
- Best practices for MDM
  - Craft implementation policy first
  - Simplify device enrollment
  - Establish self-service
  - Enforce updated MDM versions
  - Protect end-user privacy
  - Deploy containers
  - Perform data backup
  - Train employees
### 5.9.5 Bring Your Own Device (BYOD) 📓⭐
- Benefits: productivity, morale, cost savings
- Security and control issues
  - Protect sensitive data and IP
  - Protect connected networks
  - Accountability for device and data
  - Remove organizational data on termination or loss
  - Malware protection
- BYOD-specific risk
  - Access controls over device security
  - Eliminating enterprise data on exit
  - Supporting many device types and OSs
  - Ensuring backups
- Employee BYOD agreement or acceptable use agreement (AUA)
  - Devices may be seized for legal matters
  - Executive approval and monitoring
- BYOD best practices
  - Establish data ownership
  - Obtain user acceptance
  - Enforce adherence to security policies
  - Support device ownership
  - Define patch management
  - Effective antivirus management
  - Consider infrastructure requirements
  - Have exit BYOD strategy
#### Threat defines the control 📓
- Questions target one vulnerability at a time 📓
- Identify the attacker's method before choosing the defense 📓
#### Threat-to-control scenarios 📓
- Physical loss or theft → full disk encryption (data at rest) 📓
- Casual access to unattended device → passwords, screen lock, biometrics 📓
- App-level data mixing, personal malware near corporate mail → containerization or MDM 📓
- Public Wi-Fi interception → VPN or data-in-transit encryption 📓
### 5.9.6 Internet access on mobile devices
- Access via WLAN or mobile networks (4G, 5G)
- 4G: IP packet-switched; 5G: low latency, high speed
- Exposures
  - Interception of sensitive information
  - Loss or theft of devices
  - Loss of data on devices
  - Misuse of devices
  - Distractions
  - OS vulnerabilities; jailbreaking
  - Application vulnerabilities
  - Weak wireless user authentication
  - Weak file security
### 5.9.7 Audit procedures for mobile devices
- Governance: policy exists, protective features, no sensitive areas, risk assessments
- Patch management: software, antivirus, applications up to date
- Configuration and change management: gateways, Bluetooth, OS patches
- Device management: no unknown removable media, no unmanaged devices
- Device management: remote wipe/lock, lifecycle controls, cameras covered
- BYOD: policy, controls, application installation procedures
- Security monitoring: asset management, logs, download rules, MDM
- DR/BC: processes restore mobile devices and continue operations
- Awareness training: do not open unknown links
- Encryption: data at rest and in transit, TLS or VPN
### 5.9.8 Mobile payment systems
- Types of mobile payment systems
  - Digital wallets (e-wallets)
  - Mobile wallets (Apple Pay, Samsung Pay)
  - Digital currency wallets (cryptowallets): store private keys
  - Contactless payment communication: RFID, near field communication
- Mobile payment threats
  - Phishing
  - Mobile malware
  - Spoofing: fake access point
  - Unauthorized access
  - Tampering
  - Application vulnerabilities
  - Payment fraud
  - Token data compromise
  - Identity theft
  - Cloned applications
- Best practices
  - Tokenization
  - Device-specific cryptograms
  - 3D Secure
  - Strong customer authentication (SCA)
  - Continuous fraud monitoring
  - Regular audits
  - User awareness training
### 5.9.9 Wireless networks
- Wireless uses radio frequency; infrared needs line of sight
- Four categories: WWAN, WLAN, WPAN, ad hoc
- Wireless wide area networks
  - Linked by radio, satellite, mobile phone
  - 4G LTE, 5G; GSM third-generation
- Wireless local area networks
  - Access point (AP) connects to wired Ethernet
  - AP range up to 300 feet; coverage area called cell
- WEP and Wi-Fi Protected Access
  - WEP: static keys, RC4, weak
  - WPA: temporary; Personal and Enterprise modes
  - WPA-Enterprise uses RADIUS server
  - WPA2: AES, ratified 2004; has key vulnerability
  - WPA3: SAE, dictionary-attack resistance, auto-encrypts public networks
  - WEP: 40-bit, CRC-32; WPA: TKIP, MIC; WPA2: CCMP/AES, CBC-MAC
  - WPA3: SAE, protected management frames
  - WPA and WPA2 use 4-way handshake; WPA3 uses SAE
- Wireless personal area networks
  - Bluetooth: up to 49 feet (15 m), frequency hopping, 1-2 Mbps
  - Infrared: oldest, line of sight
  - ZigBee: 250 Kbps, cheaper, low energy
- Ad hoc networks
  - Shifting topologies; mobile routers on wireless links
- Wireless security threats and risk mitigation
  - Errors and omissions
  - Fraud and theft
  - Employee sabotage
  - Loss of physical and infrastructure support
  - Malicious hackers, industrial espionage, foreign government espionage
  - Malicious code
  - Threats to personal privacy
  - Requirements: authenticity, nonrepudiation, accountability, availability
  - Bluetooth sniffing: Red Fang, Bluesniff
  - Rogue and unauthorized APs
  - Identity theft and masquerading
  - Tracking physical movements
- Wireless secure encryption protocols
  - 802.1X/EAP: port-based access control, RADIUS, TACACS
  - EAP: LEAP, EAP-TLS, EAP-TTLS; EAP-MD5 breakable
  - PEAP: EAP in TLS tunnel
  - LEAP: insecure, avoid
  - MAC filter: spoofable
  - TKIP: RC4 key mixing, sequence counter; unreliable
  - CCMP: AES 128-bit; preferred for 802.11i
- Auditing procedures for wireless networks
  - Governance: approved policy, risk assessments, AP audits
  - Architecture: site survey, rogue AP, segmentation, physical security
  - Configuration: change all default AP settings, wireless IDS sensors
  - Encryption: 128-bit minimum, WPA2 with AES, no WEP
  - Credential: change defaults, disable unused interfaces, out-of-band management
  - SSID: no organization name, not broadcast
  - Monitoring: real-time monitoring, rogue device detection, session timeout
### 5.9.10 Internet of Things (IoT)
- Devices with sensors and software that exchange data
- Embedded systems: printers, smart TVs, HVAC, thermostats, medical devices
- IoT risk
  - Business risk: health and safety, compliance, privacy, costs
  - Operational risk: inappropriate access, shadow use, performance
  - Technical risk: device vulnerabilities, updates, management
  - Low software quality
  - Lack of encryption
  - Low processing power
  - Outdated hardware and software
  - Backdoor accounts
  - Poor device management
  - Interconnectedness
  - Absence of inbuilt security
- IoT security controls
  - Physical security: IMEI lock, eSIM
  - Remote access security
  - Avoid public networks
  - Encryption
  - Network isolation
  - Abnormality prevention and detection

- Security event management (SEM): identify, collect, monitor, respond, report security events
