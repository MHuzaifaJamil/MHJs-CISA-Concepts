# 5.8 Cloud and Virtualized Environments

> **Markers:** 📓 = in my Google Doc notes · ⭐ = frequently tested · ➕ = not in the review manual, verify · unmarked = gap to study. Numbering follows the ISACA CISA Review Manual 28th Ed.

- Virtualization transforms physical resources into virtual ones
- Cloud delivers virtualized resources on demand over Internet
### 5.8.1 Virtualization
- Multiple guest OSs coexist on one physical host
- Elements: server hardware, hypervisor, guest machine
- Management console gives administrative access
- Deployment types
  - Bare metal/native: hypervisor runs on hardware
  - Hosted: hypervisor runs on host OS
  - Containerization: shared kernel, isolated user-space processes
- Advantages
  - Lower hardware and operating costs
  - Smaller physical footprint
  - Multiple OS versions for testing
  - Duplicate guests support business continuity
  - Separate cost-effective development and test environments
  - Single host access control
- Disadvantages
  - Host misconfiguration affects all guests
  - Host DoS affects all guests
  - Management console compromise grants guest access
  - Host performance issues affect guests
  - Data leaks between guests if memory not controlled
  - Insecure remote management protocols expose credentials
- Host is potential single point of failure
- Typical controls
  - Securely configured hypervisors and guest images
  - Dedicated, encrypted management network
  - Patch hypervisor promptly
  - Sync to trusted timeserver
  - Disconnect unused hardware
  - Disable clipboard and file sharing services
  - Enable host inspection of guests and inter-guest traffic
  - File integrity monitoring of hypervisor
  - Strong physical and logical access controls over host
  - No VMs in DMZ; management tools on separate segment
  - Strong change management
- High-level virtualization risk
  - Rootkit as hypervisor below OS
  - Improper hypervisor resource partitioning
  - Guest tools as attack vector
  - Snapshots contain RAM content and sensitive data
  - Hosted virtualization lacks hypervisor access controls
  - Hypervisor adds attack surface
  - Host update does not update VMs
  - Backups and periodic snapshots recommended
### 5.8.2 Virtual circuits
- Logical path over packet-switched network between endpoints
- Permanent virtual circuit (PVC): always available, like leased line
- Switched virtual circuit (SVC): on demand, disassembled after use
- SVC more secure, shorter exposure, less monitoring
### 5.8.3 Virtual Local Area Network (VLAN)
- Hardware-imposed logical segmentation by switches
- Static VLAN (port-based)
- Dynamic VLAN: by negotiation, IP or hardware address
- Same-VLAN ports communicate freely; inter-VLAN via routing
- Uses: restrict broadcasts, isolate traffic, reduce sniffing, stop broadcast storms
- VLANs are not subnets
### 5.8.4 Virtual Storage Area Networks (VSAN)
- Logical partition for VM storage; isolates SAN traffic
- Suited to cloud, VDI, backup and archiving, DR
- Benefits of VSAN
  - Cost-effectiveness
  - Scalability
  - Performance
  - Flexibility: block and file storage
  - Security: replication, snapshots
  - Simplicity: embedded in hypervisor
- SAN vs VSAN
  - SAN needs dedicated hardware; VSAN uses host resources
  - SAN scaling difficult; VSAN allocates dynamically
  - SAN costly; VSAN less costly
### 5.8.5 Software-Defined Networking (SDN)
- Advantages, disadvantages, attacks, best practices
- Network virtualization; control separated from hardware
- Advantages
  - Centralized control
  - Abstracts the network
  - Facilitates scalability
  - Enhances security
  - Lower operating costs
  - Promotes network programmability
  - Enhances openness (OpenFlow)
  - Supports API security
- SD-WAN: links distributed locations; vendor-managed
- Three planes
  - Data plane
  - Control plane
  - Management plane (SNMP)
- Disadvantages
  - Latency
  - Limited management of devices
  - Network management complexity
  - Dependency on the controller
- Attacks (Figure 5.42)
  - Unauthorized access via compromised controller or application
  - Data loss: credentials stolen through compromised switches
  - Data modification: man-in-the-middle if TLS not mandatory
  - DoS: bogus calls flood controller
  - Malicious or compromised third-party applications
- Best practices
  - Careful deprovisioning
  - Regular network monitoring
  - Consider onboarding security risk
  - SDN is virtualization, not a security solution
  - Combine with other security technologies (VPN)
  - Maintain quality of service; remove default settings
### 5.8.6 Containerization
- One OS instance, multiple isolated user spaces
- Each container packages its application with its own bins/libraries ➕
- Tools: Docker (build and run), Kubernetes (orchestrate at scale)
- Benefits
  - Faster deployment
  - Platform-agnostic
  - Improved security via isolation
  - Flexibility
  - Operational efficiency
  - Cost reductions
  - Scalability
  - Portability
- Limitations
  - Best supported on Linux
  - Kernel vulnerability affects all containers
  - Networking difficult; needs network bridge
  - Monitoring challenging
  - Needs skilled management
- Best practices for container security
  - Systems hardening with vendor benchmarks
  - Monitoring container contents
  - Continuous auditing
  - Vulnerability assessments
  - Patching: update base image, rebuild application image
  - Isolation: shared kernel; run containers on VM
  - Incident response: forensics limited after replacement
  - Secure container management stack with POLP
  - Secure images
- Virtualization vs containerization
  - VMs: full isolation; containers: lightweight isolation
  - VMs run full OS each; containers share host OS
  - Containers orchestrated automatically (Kubernetes)
- Containerization isolates corporate from personal data on BYOD 📓
### 5.8.7 Secure cloud migration
- Three forms: on-premises to cloud, cloud-to-cloud, reverse migration
- Cloud migration security risk
  - Multi-tenancy
  - API vulnerabilities
  - Compliance risk
  - Uncontrolled growth
  - Data loss
  - Data security
  - Incompatibility of existing architecture
  - Reduced visibility
  - Data remanence
  - Talent gap
- Secure migration steps
  - Develop migration plan
  - Assess current on-site security
  - Establish security standards and map requirements
  - Train employees
  - Secure DevSecOps pipeline code; remove secrets
  - Evaluate regulatory requirements
  - Assess target infrastructure and data center certifications
  - Encrypt data with HTTPS and TLS
  - Clear communication
  - Strict access control
  - Automate migration
  - Data backup, possibly multiple clouds
  - Implement cloud security posture management (CSPM)
### 5.8.8 The shared responsibility model
- Provider: infrastructure, virtualization layer, hardware, physical data centers
- Customer: data, guest OS, IAM, encryption, policies, firewalls
- Shared: training, patch management, configuration management
- Customer cannot transfer data security and GRC risk
- Benefits: efficiency, reduced IT staff costs, enhanced protection, expertise
- Cloud deployment models
  - Public, private, hybrid
  - Public cloud: provider secures the cloud; customer secures in the cloud
  - Private cloud: dedicated infrastructure, more control, suits healthcare and finance
  - Hybrid cloud: customer segments data per use case
  - Community cloud: shared compliance across a consortium 📓⭐
  - Community cloud: member-managed, high data security
  - Multi-cloud: combines public clouds; larger attack surface
- Cloud service models: IaaS, PaaS, SaaS
  - IaaS: processing, storage, networks; freedom over OS and applications
  - PaaS: application development sandbox for developers
  - SaaS: complete provider applications via thin client
- SRM best practices
  - Carefully review SLA
  - Prioritize data security
  - Ensure robust IAM
  - Identify trusted cybersecurity partner
  - Embrace DevSecOps
### 5.8.9 Key risk in cloud environments
- CSA top threats
  - Insufficient identity, credentials, access and key management
  - Insecure interfaces and APIs
  - Misconfiguration and inadequate change control
  - Lack of cloud security architecture and strategy
  - Insecure software development
  - Unsecured third-party resources
  - System vulnerabilities
  - Accidental cloud data disclosure
  - Misconfiguration of serverless and container workloads
  - Organized crime, hackers and APTs
  - Cloud storage data exfiltration
### 5.8.10 DevSecOps
- Benefits and best practices
- Convergence of development, security, operations
- Security integrated in CI/CD pipelines from start of SDLC
- DevOps: dev plus IT ops; SecOps: security plus IT ops
- Benefits
  - Fast, cost-effective, secure delivery
  - Addresses security issues proactively
  - Fast vulnerability remediation
  - Automation-driven development
  - Simplified compliance reporting
  - Standardized security efforts
- Best practices
  - Shift security left
  - Incorporate compliance processes
  - Invest in security training
  - Improve workplace culture
  - Enhance observability and monitoring
  - Support accountability, traceability, auditability
