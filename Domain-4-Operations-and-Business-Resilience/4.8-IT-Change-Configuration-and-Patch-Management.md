# 4.8 IT Change, Configuration and Patch Management

> **Markers:** 📓 = in my Google Doc notes · ⭐ = frequently tested · ➕ = not in the review manual, verify · unmarked = gap to study. Numbering follows the ISACA CISA Review Manual 28th Ed.

- Change control moves changes: test, then QA, then production
- IS operations ensures production integrity; final approver
- Change management covers
  - Hardware modifications
  - Off-the-shelf releases and upgrades
  - Application patching
  - Network device configuration (firewalls, routers, switches)
- Procedures ensure
  - Relevant personnel informed of change and timing
  - Documentation complete and compliant
  - Job preparation, scheduling, operating instructions set
  - User and project management approve test results
  - Data file and system conversion accurate and approved
  - Operations personnel test and approve turned-over jobs
  - Legal or compliance aspects considered
  - Risk reviewed; rollback plan developed
- Change request process: formalization, documentation, authorization, testing, implementation, user communication
- Change categories: emergency, major, minor
### 4.8.1 Patch management
- Acquire, test, install patches to maintain current software and address security risk
- Tasks
  - Maintain current knowledge of available patches
  - Decide which patches suit which systems
  - Install properly; test after installation
  - Document procedures and configurations
- Automation products exist; patches can cause more problems
- Backup and test on non-critical systems first
- Patch management is part of change management
### 4.8.2 Release management
- Release: collection of authorized changes; unique identifier
- Release types
  - Major: significant change or new functionality; planned timetable
  - Minor: small enhancements and fixes; supersedes emergency fixes
  - Emergency: urgent fixes; limited testing; avoid, raises error risk
  - Delta (partial) release: only items modified since last release
- Back-out capability to restore previous state; contingency plans before release
- Release planning
  - Consensus on contents
  - Release strategy: phasing by time, location, unit, customer
  - High-level schedule
  - Resource levels incl. overtime
  - Roles and responsibilities
  - Rollback plans
  - Quality plan
  - Acceptance by support groups and customer
- Release management puts tested changes into production
### 4.8.3 IS operations
- Day-to-day support and management of infrastructure, systems, applications, data
- Staff tasks
  - Execute and monitor scheduled jobs
  - Facilitate timely backup
  - Monitor unauthorized access to sensitive data
  - Monitor adherence to operations procedures
  - Participate in DRP tests
  - Monitor performance, capacity, availability, failure
  - Troubleshooting and incident handling
- Documentation
  - Operating instructions and job flows
  - Monitoring procedures
  - Error detection procedures
  - Problem handling and escalation
  - Backup and recovery procedures
- IS operations reviews
  - Tour of information processing facility (IPF)
  - Observation of IS personnel: supervision, standards adherence, management review
  - Operator access: restricted to files, libraries, utilities, production source code, correction of data
  - Operator manuals: startup/shutdown, failure, records retained, routine duties
  - Access to library
    - Librarian cannot access hardware; only data management system
    - Sign-in/out logs for media; scheduling software restricts removal
    - Receipt and return of foreign media
  - Contents and location of offline storage
    - Labeled offline media; library away from computer room
    - Offsite backup labeling, delivery, retrieval; encryption in transit
    - Media inventory with storage locations; secure disposal with signatures
    - Internal labels ensure correct media mounted
  - Data entry
    - Authorized, signed input documents; batch totals reconciled
    - Separation of keying and review duties; control reports
  - Lights-out operations
    - Remote master console access secured
    - Contingency plans identify disaster in unattended facility
    - Automated operation software tested at recovery site
    - Program change and access controls; errors always notify operator
- Change process undocumented plus failed migrations: root cause analysis first 📓
