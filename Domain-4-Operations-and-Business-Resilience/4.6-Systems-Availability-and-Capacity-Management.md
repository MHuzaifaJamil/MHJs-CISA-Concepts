# 4.6 Systems Availability and Capacity Management

> **Markers:** 📓 = in my Google Doc notes · ⭐ = frequently tested · ➕ = not in the review manual, verify · unmarked = gap to study. Numbering follows the ISACA CISA Review Manual 28th Ed.

- System software: utilities and programs ensuring integrity, controlling program flow, managing interfaces
- Examples
  - Access control software
  - Data communications software
  - Database management software
  - Program library management systems
  - Disk management systems
  - Network management software
  - Job scheduling software
  - Utility programs
### 4.6.1 IS architecture and software
- Hardware and firmware at base of hierarchy
- Nucleus (kernel) functions
  - Handling interruption
  - Process creation/destruction
  - Process state switching
  - Dispatching
  - Process synchronization
  - Interprocess communication
  - I/O support
  - Memory allocation and release
- Virtual storage lets programs address more than real memory
### 4.6.2 Operating systems
- OS: interface between user, processor, applications; scheduler and traffic controller
- Manages processors, real memory, auxiliary memory, I/O devices
- OS needs vary
  - Stand-alone microcomputer: catalog files, load programs
  - Mainframe: extensive resources, high reliability (z/OS)
  - Multi-user server: multiprocessing, multitasking, multithreading (UNIX)
  - Networked microcomputer as specialized server
  - Virtual servers: one physical server partitioned
- Software control features or parameters
  - Parameters customize standard software and activate logging
  - Control data management, resource management, job management, priority setting
  - Review of parameters best shows how OS controls function
  - Poor implementation causes undetected errors, unauthorized access, inaccurate logging
- Software integrity issues
  - Protect from deliberate and unintentional modification
  - User programs cannot interfere with privileged programs
  - Process isolation between concurrent processes
  - Least privilege for processes
  - Prevent nonprivileged users running privileged instructions
  - z/OS: SYSGEN, initial program load, SYS1.PARMLIB parameters protect supervisory state
  - Windows registry: monitor changes
  - UNIX/Linux: secure kernel, start-up, file-sharing config files
  - Patch currency prevents compromise
- Operating system reviews
  - System software selection procedures
    - Alignment with EA, IS plans, business objectives
    - Same selection criteria for all proposals
    - Cost-benefit: financial, maintenance, hardware, training, reliability, security, vendor stability
  - System software security
    - Restrict circumvention of logical access controls
    - Limit access to system interrupt capability
    - Patch management; secure master consoles
    - Change vendor-supplied installation passwords
  - IT asset management: owner, contracts/SLAs, license compliance
  - System software implementation controls
    - Change and authorization procedures; access security features
    - Documentation, testing documentation, audit trails
    - Access controls over production software
  - System documentation
    - Installation control statements, parameter tables, exit definitions, activity logs
  - System software change controls
    - Authorization documentation: access changes, attempted violations followed up
    - Maintenance: vendor-supported versions, defined patching process
    - Library access limited; changes tested and authorized before production
  - Installation of changed system software
    - Predecessor updates applied; schedule at low-impact times
    - Written test plan; retest after problems
    - Fallback or restoration procedures
### 4.6.3 Access control software
- Detects or prevents unauthorized access to data, functions, programs, updates
- Detailed coverage in chapter 5
### 4.6.4 Data communications software
- Transmits messages or data between points, locally or remotely
- Simple system: transmitter, transmission path, receiver
- One-way versus two-way communication
- Concerned only with correct transmission, not content
- Layered; minimum physical and data link layers
- Supports EFT, DBMS, EDI, forums and email
- Interfaces with OS, applications, databases, network control, job scheduling, consoles
### 4.6.5 Utility programs
- Five functional areas
  - Understanding application systems: flowcharting, transaction profile analyzer, executive path analyzer, data dictionary
  - Assessing data quality: data manipulation, database dump, data comparison, query
  - Testing program function and integrity: test data generator, online debugging, output analyzer, network simulator
  - Faster program development: visual display, library copy, text editor, report and code generators
  - Operational efficiency: CPU/memory monitors, communication line analyzers
- PC/server utilities: defragmenting, volume initialization, system image save/restore, file recovery, peripheral testing
- Risk: can bypass security and leave no audit trail; restrict access
### 4.6.6 Software licensing issues
- Copyright compliance avoids penalties and reputational risk
- Licensing agreement: contract of terms between owner and user
- Free license types
  - Open source: use, modify, redistribute (e.g., Linux, GNU GPL)
  - Freeware: free, no source redistribution; may be personal-use only
  - Trial: demo or evaluation with limited function
- Paid license types
  - Per CPU (cores)
  - Per seat (unique users)
  - Concurrent users
  - Utilization (CPU busyness or active users)
  - Per device
  - Enterprise: unlimited use in organization
  - Mixed
- Other pricing metrics: transaction volume, data volume, revenue share
- Detecting violations
  - Review list of standard, used, licensed software
  - Obtain software contracts
  - Scan network for installed software
  - Review server CPUs and cores
  - Compare licenses with installed software
- Preventing violations
  - Good software asset management
  - Centralize control, distribution, installation
  - Restricted workstations (locked drives, USB ports)
  - Regular endpoint scans against asset list
  - Policies and signed user agreements
- Contractual compliance; may need legal opinion
- Publisher audit rights: collect licenses up front
- DR arrangements may need extra licenses and metering software
### 4.6.7 Source code management
- Source code is human-readable; converted to object code by assemblers and compilers
- Contains intellectual property; restrict access
- Access varies: no source (escrow), packaged (license), bespoke (full access)
- Tied to change, release, QA, information security management
- Version control system (VCS) / revision control software
  - Central repository; check out, check in creates revision
  - Synchronize changes and resolve conflicts
  - Branching from trunk
  - Examples: Apache Subversion, Git (distributed), GitLab, GitHub
  - DVCS replicates repository locally; work remotely
- VCS advantages
  - Control source code access
  - Track changes
  - Concurrent development
  - Rollback
  - Branching
- Auditor checks
  - Who has access to source code
  - Who can commit to production
  - Source-to-object alignment
  - Alignment with change and release management
  - Backups including offsite and escrow
### 4.6.8 Capacity management
- Planning and monitoring of computing and network resources
- Capacity plan based on user and IS management input; review at least annually
- Key planning information
  - CPU/vCPU utilization
  - Storage utilization
  - Telecommunications
  - LAN and WAN bandwidth
  - I/O channel utilization
  - Number of users
  - New technologies and applications
  - VM density on physical hosts
  - SLAs
- Hosting choice: distributed small servers, consolidated large servers, cloud
  - Application stacking raises outage impact
  - Cloud: on-demand capacity but supplier reliance
- Server farms; private clouds
- Include storage/SAN, switches, routers, VLANs
- Threshold example: add disk at 80 percent storage
- Benefits
  - Defer cost of new capacity
  - Avoid performance failure via threshold monitoring
  - Forecasting through application sizing and modeling
- Capacity planning and monitoring elements
  - Developing: plan of current and future needs
  - Monitoring: components against agreed service levels
  - Analyzing: trends and baselines
  - Tuning: optimize for workload
  - Implementing: introduce new capacity
  - Modeling: forecast resource behavior
  - Application sizing: users, transactions, storage, server needs
- Unmonitored disk space causes systemic failures, including at recovery sites 📓
