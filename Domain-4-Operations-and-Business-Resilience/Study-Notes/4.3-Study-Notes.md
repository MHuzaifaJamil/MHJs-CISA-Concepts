## 4.3 Overview: Job Scheduling and Production Process Automation

### Basics

- Definition: A production job is a program run as part of normal operations.
- Use: Batch jobs process large data volumes without user interaction.
- Audit impact: Uncontrolled jobs can corrupt production data or miss deadlines.
- Definition: Job schedule is a list of jobs to run.
- Definition: It states run order, dependencies, and conditions that trigger execution.
- Use: Ensures work completes in the right sequence and on time.
- Audit impact: A weak schedule causes missed processing, wrong sequence, and unauthorized runs.
- Example: Nightly payroll must wait for the timekeeping import to finish.
- Definition: Job scheduling covers more than batch jobs.
- Use: It also schedules backups and other maintenance activities.
- Audit impact: Missed backups hurt recoverability, so backup jobs need monitoring too.
- Complex environments move thousands of data files daily.
- Complexity is why automated software controls scheduling.
- Job scheduling is a major IT function; its controls are taken seriously.

### Priorities and resources

- High-priority jobs receive optimal resource availability.
- Maintenance (backup, system reorganization) runs in nonpeak times where possible.
- Low-priority jobs run when time becomes available.
- Use: Schedules keep demand manageable and let on-request jobs run without delay.
- Audit impact: Priority must be justified and tied to business criticality.
- Example: Month-end reporting outranks an archive cleanup job.
- Job scheduling ensures IS resources are used optimally for processing needs.
- Continuous availability makes scheduling harder than before.
- Reason: Little downtime remains for maintenance or long-running jobs.
- Audit impact: Check that maintenance windows exist and do not threaten service levels.

### Process automation

- Definition: Production process automation means software, not operators, drives routine runs.
- Use: Cuts manual effort, human error, and operator discretion.
- Audit impact: Automation moves risk to the tool and its configuration.
- ⚠ Check: Manual says little on automation beyond scheduling software.

## 4.3.1 Job scheduling software

- Definition: System software used where many batch routines run.
- Use: Sets up daily work schedules.
- Use: Automatically decides which jobs to submit for processing.
- Audit impact: It has privileged control over production, so access must be restricted.
- Software requires ongoing maintenance and optimization.
- Reason: Outcomes drift as workloads and dependencies change.
- Audit impact: Look for evidence of periodic review of schedule definitions.

### Advantages

- Job information is set up once.
- Result: Less reliance on operators and lower error probability.
- Job dependencies are defined in the tool.
- Result: If a job fails, dependent jobs relying on its output do not run.
- Example: Failed file extract stops the load job, preventing partial data posting.
- Logs record all job successes and failures.
- Audit impact: These logs are key audit evidence.
- Security controls access to production data.
- Manual task burden is reduced or eliminated.

### Exam traps

- Best control for blocking dependent jobs after a failure is defined dependencies.
- Wrong: Operator vigilance is manual and error-prone.
- Scheduling software benefit is consistency and logging, not eliminating all review.
- Software needs maintenance; "set once, never reviewed" is a weakness.

## 4.3.2 Scheduling reviews

- Definition: An audit approach for reviewing workload job scheduling and personnel scheduling.
- Use: Confirms jobs run on time, authorized, and failures are handled.
- Checkpoints in production jobs are detective controls 📓 ⭐.
- Definition: A checkpoint marks a point where processing state is verified.
- Use: Monitors and identifies processing errors during a run.
- Audit impact: Checkpoints find errors but do not prevent them.

### Regularly scheduled applications

- Review input deadlines.
- Review data preparation time.
- Review estimated processing time.
- Review output deadlines.
- Items should appear in service level agreements (SLAs).
- Items should function according to those SLAs.
- Critical applications must be identified and given the highest priority.
- Priorities for other applications must be established and justified.
- ➕ The manual also lists procedures for collecting and analyzing key performance indicators.
- ⚠ Check: The outline omits the performance indicators row; the manual includes it.

### Job schedule

- Rush and rerun jobs must be scheduled consistent with their assigned priority.
- Procedures should optimize computer resources while meeting service requirements.
- Operators record jobs to be processed and required data files.
- Operators schedule jobs on a predetermined basis, using automated or manual tools.

### Daily job schedule

- Personnel per shift must be adequate for the workload.
- The daily schedule serves as an audit trail.
- It gives each shift the work, sequence, and timing of lower-priority work.
- Operators pass a statement of completed work to the next shift.
- The statement includes reasons any scheduled work was not finished.

### Console log

- Check that jobs ran and completed according to schedule.
- All job failures must be flagged and communicated for action.
- Root causes of failures must be investigated and determined.
- Reasons for failures must be valid.
- Failures must be communicated to appropriate end-user stakeholders.
- Audit impact: Console logs are the main evidence of actual run history.

### Exception processing logs

- Definition: Exception (request-only) jobs run outside the normal schedule.
- Operators need written or electronic owner approval before scheduling them.
- Operators record all exception processing requests.
- Operators review the request log for appropriateness of procedures performed.
- Audit impact: Unapproved ad hoc jobs are a path to unauthorized data changes.

### Restarting jobs

- Restarted jobs must be properly authorized and logged for IS management.
- Rerun procedures must ensure the correct input files are used.
- Subsequent jobs in the sequence rerun if appropriate.
- Restarted jobs must be verified for completion.
- Audit impact: Wrong input files on rerun cause duplicate or missing postings.
- Example: Rerunning a billing job on yesterday's file double-charges customers.
- ⚠ Check: Outline says "management reviewed" under restarts; manual states logging for IS management.

### Personnel

- Only authorized personnel may assign or change job schedules and priorities.
- Manual ties this to management review of who holds that capability.
- Audit impact: Unrestricted schedule changes allow unapproved processing and priority manipulation.

### Exam traps

- Checkpoints are detective, not preventive or corrective.
- Reason: They identify errors after they occur in processing.
- Best audit evidence of what ran: console log, not the planned schedule.
- Planned schedule shows intent; the log shows actual execution.
- Highest rerun risk is wrong input files, not rerun speed.
- Schedule changes need authorization; operator convenience is not a valid reason.
- Critical applications get highest priority regardless of which team requests resources.

## Takeaway

- Job schedules define jobs, order, dependencies, and execution conditions.
- Scheduling software cuts operator error and blocks dependent jobs after failures.
- Checkpoints are detective controls that identify processing errors.
- Console logs prove actual execution; schedules only show intent.
- Reruns and exception jobs need authorization, logging, and correct input files.
- Only authorized staff may change schedules and priorities.
