## 4.13 System resilience basics

### Resilience

- Definition: ability of a system to absorb disruption and keep core functions running.
- Use: limits performance loss during failures, stress, or attacks.
- Audit impact: auditor checks that critical systems have no unprotected single failure points.
- Threats covered: hardware failure, network outage, cyberattack, software bug.

### Building blocks

- Redundant components: duplicate parts that take over when one part fails.
- Failover mechanism: automatic switch to a standby component on failure.
- Backup strategy: copies of data kept so integrity can be restored.
- Audit impact: auditor verifies each building block exists and has been tested.
- Resilience keeps services running; recovery restores them after interruption. Both are needed.
- Example: a bank runs two payment servers so one crash does not stop transfers.

### Single point of failure

- Definition: one resource whose loss stops service or production.
- Use: the term guides redundancy design and risk assessment.
- Audit impact: every single point of failure found is a finding to report.

## 4.13.1 Application resiliency and disaster recovery methods

### Clustering

- Definition: a group of servers (nodes) running the same application together.
- Definition: each node has a cluster agent, which is software.
- Definition: management software controls and tunes the cluster behavior.
- Use: protects against a single point of failure.
- Use: main purpose is higher availability.
- Audit impact: auditor confirms the cluster covers every critical application tier.
- Audit impact: auditor checks that failover has actually been tested.
- Two deployment types exist: active-passive and active-active.

### Active-passive cluster

- Definition: application runs on one active node only.
- Definition: passive nodes wait unused until the active node fails.
- Use: agents watch the application and restart it on a surviving node.
- Use: application need not be cluster-aware.
- Use: this makes it a simple, common availability and recovery method.
- Data is replicated from the active node to the other nodes.
- Demands on the environment are lower than active-active.
- Audit impact: restart takes time, so brief downtime is expected.
- Audit impact: auditor verifies replication is current and failover time meets recovery targets.
- Example: a database runs on node A; node B starts it if A dies.

### Active-active cluster

- Definition: application runs on every node at the same time.
- Use: agents balance load and coordinate concurrent data access.
- Use: users normally see little or no downtime when a node fails.
- Unfinished transactions on a failed node may be lost or rerun elsewhere.
- Application must be built to be cluster-aware.
- Shared storage must be reachable by all nodes.
- Network latency demands are greater than for active-passive.
- Benefits: quick recovery, load balancing, and scalability.
- Less common than active-passive.
- Audit impact: auditor checks transaction integrity when a node fails mid-transaction.
- Audit impact: shared storage becomes a new single point of failure to review.
- Example: three web servers share traffic; losing one only reduces capacity.

### Combined and geographic clusters

- Combined design: active-active inside a site, active-passive between sites.
- Active-active inside a site protects against local hardware or software failure.
- Active-passive between sites protects against whole-site failure.
- Metro-cluster: cluster whose nodes span one city.
- Geo-cluster: cluster spanning cities, countries, or continents.
- Audit impact: wider distance raises latency and affects which cluster type is feasible.
- ⚠ Check: geo-cluster preference for active-passive is my inference from latency. ➕
- Building cluster software in-house is rarely economical.
- Vendor products are the usual choice.
- Audit impact: auditor reviews vendor support and licensing for the cluster software.

### Exam traps (4.13.1)

- Active-passive needs no cluster-aware application; active-active does.
- Active-active gives near-zero downtime; active-passive requires a restart delay.
- Active-active needs shared storage; active-passive needs data replication.
- Clustering raises availability; it does not replace backups.
- A site-wide disaster defeats single-site active-active; between-site passive nodes cover it.

## 4.13.2 Telecommunication networks resiliency and DR methods

### Responsibility and risks

- Telecommunications are key to business processes, so continuity is prioritized.
- The organization, not the local exchange carrier, must ensure communication continuity.
- The carrier has no duty to provide backup services.
- Many carriers back up their main components anyway.
- Audit impact: auditor checks the plan does not assume carrier backup.
- Networks face natural disasters, like data centers do.
- Unique risks: central switching office disaster, cable cuts, software glitches, hacking, human error.

### Capabilities the BCP must cover

- IPF means information processing facility.
- IPF BCP must cover voice circuits.
- It must cover WANs, meaning links to distributed data centers.
- It must cover LANs, meaning workgroup PC connections.
- It must cover third-party EDI providers.
- Capacity needs are identified per outage threshold, for example 2, 8, or 24 hours.
- UPS capacity must cover both telecommunications and computer equipment.
- Audit impact: auditor compares UPS sizing to the longest outage threshold.

### Redundancy

- Definition: spare capacity or duplicate parts used when the primary path fails.
- Use: removes single points of failure in the network.
- Extra capacity: surplus used when normal primary transmission is unavailable.
- Example: a second LAN cable on an alternate route.
- Multiple paths between routers.
- Dynamic routing protocols such as OSPF and EIGRP reroute traffic automatically.
- OSPF is Open Shortest Path First.
- EIGRP is Enhanced Interior Gateway Routing Protocol.
- Failover devices remove single points of failure in routers, switches, and firewalls.
- Device configurations should be saved to TFTP servers for recovery.
- TFTP is Trivial File Transfer Protocol; manual spells it "Transport".
- ⚠ Check: TFTP lacks authentication and encryption (not in manual); secure the server. ➕
- Audit impact: auditor checks configuration backups exist, are current, and are access-controlled.

### Alternative routing

- Definition: sending traffic over a different medium, network, circuit, or endpoint.
- Use: keeps traffic flowing when the normal network is unavailable.
- Alternate media: copper or fiber.
- Counter-rotating fiber rings carry data in two directions.
- The two directions use separate cable sheaths for extra protection.
- Such rings currently connect through one central switching office.
- Future expansion may add a second central office.
- Some carriers offer routes to different points of presence or central offices.
- Other alternatives: cellular, microwave, and couriers instead of electronic transmission.
- Audit impact: a ring via one central office remains a single point.
- ⚠ Check: outline lists "Alternative routing" twice; the manual lists it once.

### Diverse routing 📓⭐

- Definition: routing traffic through split-cable or duplicate-cable facilities.
- Use: gives physical path redundancy with different or duplicate cable sheaths.
- Different sheaths may still share one conduit.
- A shared conduit means shared interruptions, such as one dig cut.
- Premises entrance to and from the customer site may also share one conduit.
- Subscribers can request diverse and alternate routing, including dual entrance facilities, from the carrier.
- Dual entrance facilities are costly and time-consuming to obtain.
- Most carriers offer alternate and diverse routing.
- Most services still travel over terrestrial media.
- Ground-based cables face risk from aging city infrastructure.
- Cable facilities often share rooms with mechanical and electrical systems.
- Audit impact: auditor checks that diverse paths do not converge in one conduit.
- Example: two cable sheaths enter the building through one duct; one cut kills both.

### Long-haul network diversity

- Definition: using several long-distance carriers over terrestrial circuits.
- Use: long-distance access continues if one carrier fails.
- Carriers use automatic rerouting software and redundant lines for near-instant recovery.
- Audit impact: auditor verifies the recovery facility has these capabilities.

### Last-mile circuit protection

- Definition: redundant connections between the facility and the local communications loop.
- Use: keeps access during a local carrier disaster.
- Options: local carrier terrestrial circuits, microwave, coaxial cable.
- Alternate local carrier routing is also used.
- Audit impact: auditor checks the last mile is not a single carrier dependency.

### Voice recovery

- Definition: methods to keep telephone service during a failure.
- Use: critical for voice-dependent services, especially financial and retail.
- Common approaches: redundant cabling and Voice over Internet Protocol (VoIP).
- Audit impact: auditor confirms voice has its own recovery plan, not only data.

### Satellite connectivity

- Definition: network access through broadband or temporary satellite service.
- Use: covers locations where other telecommunication options are unavailable.
- Audit impact: auditor checks satellite is documented as a contingency path in the plan.
- ⚠ Check: manual omits satellite latency and capacity limits. ➕

### Exam traps (4.13.2)

- Split-cable or duplicate-cable routing is diverse routing, not alternative routing.
- Alternative routing means a different medium, network, circuit, or endpoint.
- Multiple long-distance carriers describe long-haul diversity, not diverse routing.
- Redundant local circuits, microwave, or coaxial describe last-mile protection.
- Different sheaths do not guarantee independence; the conduit may be shared.
- The carrier is not responsible for the customer's backup connectivity.
- Auditor verification of automatic rerouting belongs to long-haul diversity at the recovery facility.

## Takeaway

- Resilience removes single points of failure through redundancy, failover, and tested backups.
- Active-passive is simple and restarts; active-active is faster but needs cluster-aware applications.
- Combine active-active locally and active-passive between sites.
- The organization, not the carrier, owns telecommunication continuity.
- Diverse routing means split or duplicate cables; check conduits are not shared.
- Match terms: alternative routing, long-haul diversity, last-mile protection each have distinct meanings.
