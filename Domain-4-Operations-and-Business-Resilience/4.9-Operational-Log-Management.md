# 4.9 Operational Log Management

> **Markers:** 📓 = in my Google Doc notes · ⭐ = frequently tested · ➕ = not in the review manual, verify · unmarked = gap to study. Numbering follows the ISACA CISA Review Manual 28th Ed.

- Logs (audit trails) record activities, system events, user interactions
- Log monitoring can be a compensating control (e.g., small staff, no SoD)
- Log records establish
  - Type, time, location, source, outcome of event
  - Identity of individuals or objects involved
### 4.9.1 Types of logs
- Event log: traffic, logins, failed passwords; detective control
- Server log: activity of a server over a period
- System log: OS startup, changes, shutdowns, errors, warnings
- Access log: people or bots accessing files; compensating control
- Change log: chronological changes; supports change management
- Availability log: uptime; shows whether SLAs met
- Resource log: connectivity issues, capacity limits; early breach indicator
- Threat log: firewall profile matches; early warning
- Database log: inserts, updates, deletions
- Error log: problem details for resolution
- Firewall log: traffic through firewall
- Operating system log: file versions, programs run, utility/service ID use
- Application log: efficiency, authorized changes, unauthorized use
- Access control log: controls over critical files, databases, programs
- Intruders alter logs; protect via centralized SIEM on secure server
- Secure logging preserves evidence authenticity for court use
### 4.9.2 Log management
- Purpose: availability, integrity, confidentiality of log data
- Six-step log management cycle
- Three-tier infrastructure
  - Log generation: hosts producing logs
  - Log analysis and storage: collectors/aggregators, log or database servers
  - Log monitoring: consoles, reports; least privilege for console users
- Retention supports follow-up investigations and long-undetected attacks
- Data collection
  - Sources: servers, network devices, databases, OSs, applications
  - Collection agents or centralized solutions
  - Minimum: timestamp, user, event ➕
- Generating alerts
  - Different logs alert different teams (syslog to user; threat log to security)
  - Auditor checks parameters, receipt, prompt action
- Storing and protecting logs
  - Centralized log system; defined retention policy
  - Encrypted storage; offsite backups
  - Role-based access controls
  - Automated backup schedule
- Analyzing log data
  - Real-time alerting on thresholds
  - Deeper analysis across correlated logs
  - Log parsing and normalization of formats and timestamps
  - Regular expressions and parsing libraries
  - Event correlation (SIEM)
  - Pattern matching for attack signatures
  - Statistical analysis: mean, median, standard deviation, time-series
- Reporting concerns
  - Documented reporting and escalation procedures
  - Classify by severity or criticality
  - Incident response plan: roles, communication, containment, post-incident analysis
  - Report content: source, affected assets, impact, actions, recommendations
  - Follow-up and stakeholder communication
  - Adhere to regulatory requirements
- Log timestamp synchronization is critical for forensic timelines 📓⭐
- Integration with SIEM and IT governance
  - SIEM adds multi-source integration, real-time monitoring, correlation
  - Governance frameworks: COBIT, ITIL
  - Incident management: root cause, event sequence
  - Problem management: recurring patterns
  - Change management: verify before, during, after changes
  - Service monitoring: uptime, response time, error rates, SLA compliance
  - Configuration management: audit trail of changes
  - Knowledge management: articles, troubleshooting guides, FAQs
