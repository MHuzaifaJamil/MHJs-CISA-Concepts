# 4.14 Data Backup, Storage and Restoration

> **Markers:** 📓 = in my Google Doc notes · ⭐ = frequently tested · ➕ = not in the review manual, verify · unmarked = gap to study. Numbering follows the ISACA CISA Review Manual 28th Ed.

- Laws and regulations affect data handling and retention
### 4.14.1 Data storage resiliency and DR methods
- RAID: combines physical disks into logical units for redundancy, performance, or both
  - Storage arrays hide complexity; staff must still understand RAID levels
- Array replication modes
  - Synchronous: write confirmed only after remote write
  - Asynchronous: scheduled replication
  - Adaptive: switches by network load
- Array-based (hardware) replication transparent to application
- Host-based replication for servers without disk arrays
- Remote storage: off-site physical media 📓
- E-vaulting: electronic transmission to a remote site 📓
### 4.14.2 Backup and restoration
- Plan per BIA, RPO, RTO; minimize data loss within budget
- Secondary storage: mirrored disks (local or remote), network storage
- Removable media stored in offsite libraries
  - Number and location based on use availability and interruption risk
  - Inventory manual (offsite librarian) or automatic (vaulting)
  - Integrated backup solutions replace manual catalogs
- Immutable backup: cannot be altered, deleted, or encrypted, even by admins
- Offsite library controls
  - Secure physical access to authorized personnel
  - Encrypt backup media, especially in transit
  - Construction withstands fire, heat, water
  - Located away from data center, not subject to same disaster
  - Inventory of media and files for retention time
  - Record of media moved in and out
  - Catalog of file versions and locations, protected from disclosure
  - Retention per enterprise policy
- Cloud backup
  - Offsite library in third-party provider data center
  - Disconnected infrastructure resists ransomware targeting backups
  - Encrypt data in transit and in cloud; keys on need-to-know
  - Verify backup and restore times meet RTO and RPO
  - Real restore may need large network transfers; samples understate
- Security and control of offsite facilities
  - As secure as originating site: locked doors, no windows, surveillance
  - Not easily identifiable from outside
  - Environmental monitoring: humidity, temperature, air
  - UPS, raised floor, smoke and water detectors, tested fire suppression
  - Paper records not a fire hazard
- Media and documentation backup
  - Duplicate data and documentation offsite as recovery prerequisite
  - Secure transport of physical media and mirrored backups
- Types of backup devices and media
  - Selection factors: standardization, capacity, speed, price
  - Removable media: CDs, DVDs, removable hard drives, solid-state drives
  - Tape: DDS, DAT, DLT, AIT, LTO
  - Disk-based: virtual tape libraries (VTL), disk snapshots, host-based or array-based replication
  - Snapshots
    - Momentary copies; full or changed blocks only
    - Mount on another server to offload production
  - Disk-based backup suits virtualized servers; whole VMs replicated
  - Offsite copies get same security as originals
- Periodic backup procedures
  - VTL: disk storage emulating tape library; replicated to backup site
  - Host-based replication: synchronous or asynchronous
  - Disk-array-based replication: hidden from servers; via SAN or LAN
  - Backup per RPO; data folders more often than configuration/software files
  - Online systems: nightly/hourly backups or replication
  - Automated backup and media management avoids operator error
  - Agents on servers collect data and ship to backup servers
- Frequency of rotation
  - Retain copy at point in time plus changes since
  - Frequency and retention generations per application
  - Anticipate failure at any processing step
  - Legacy: retain master files at intervals; transaction files match masters
  - DBMS needs specialized backup agent for make and version
  - Arrange vendor software licenses for alternate site beforehand
  - Custom software: object and source libraries, current patches at all locations
  - Compatible backup hardware offsite; support agreements for long-term retention
  - Documentation preserved offsite and updated
  - Adequate backup is prerequisite to recovery
- Types of media and documentation rotated
  - Software: OS, languages, compilers, utilities, applications
  - Paper: operational guides, user manuals, records, data files, databases
  - Offsite storage classification
    - Operating procedures: run books, job stream control, OS manuals
    - System and program documentation: flow charts, source listings, logic, user manuals
    - Special procedures: exception, variation, emergency processing
    - Input and output source documents: copies, microfiche, microfilm
    - BCP copy
  - Sensitive data in fire-resistant magnetic media container
  - Policy on what is stored and how long; rotation via management software
- Missing backup policy is a major risk 📓
### 4.14.3 Backup schemes
- Three main schemes: full, incremental, differential; often combined
- Full backup: copies everything; base for incrementals 📓
  - One backup set; single repository for restore
  - Needs more time and media capacity
- Incremental backup 📓⭐
  - Captures only changes since the last backup 📓
  - Main goal: faster backups, fewer resources 📓
  - Restore needs multiple sets in sequence 📓
  - Saved storage is a secondary benefit 📓
  - Data integrity is required for all backup types 📓
  - Copies changes since last incremental or full backup
  - Restore needs full plus all incremental sets; slower restore
- Differential backup
  - Copies all changes since last full backup (cumulative)
  - Faster and smaller than full; restore needs last full plus last differential
  - Faster restore than incremental; slower backup and more media than incremental
- Method of rotation
  - Grandfather-father-son
    - Daily backups (son) rotate through the week
    - Last backup of week becomes weekly (father)
    - Last weekly of month becomes monthly (grandfather)
    - Last monthly of year becomes yearly
    - Monthly and annual media retained, not rotated
  - Offsite media not returned until replacements are safely offsite
  - Variations for quarterly backups and redundancy
- Record keeping for offsite storage
  - Backup media: data set name, volume serial number, creation date, accounting period, bin number
  - Critical documentation: name, location, system, date of last update
  - Automated media management records this
  - Receipt and shipment logs for media carried between facilities
- 3-2-1 backup strategy
  - One primary backup and two copies
  - Two different media types
  - At least one copy offsite
  - May be unavailable from cloud providers
