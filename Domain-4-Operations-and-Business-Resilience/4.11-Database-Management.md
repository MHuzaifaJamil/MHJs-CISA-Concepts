# 4.11 Database Management

> **Markers:** 📓 = in my Google Doc notes · ⭐ = frequently tested · ➕ = not in the review manual, verify · unmarked = gap to study. Numbering follows the ISACA CISA Review Manual 28th Ed.

- DBMS organizes, controls, uses data; functions: less redundancy, faster access, basic security
- Data organized in multilevel schemes; field is lowest level
- Data dictionary
  - Active: required entries; aids processing (validation, print formats)
  - Passive: repository for viewing or printing
- Access control levels
  - User and database
  - Program and database
  - Transaction and database
  - Program and data field
  - User and transaction
  - User and data field
- DBMS advantages
  - Data independence
  - Ease of support and flexibility
  - Transaction processing efficiency
  - Reduced redundancy
  - Maximized consistency
  - Lower maintenance cost via sharing
  - Enforced data/programming standards
  - Enforced data security
  - Stored data integrity checks
  - Ad hoc access via query languages/application generators
### 4.11.1 DBMS architecture
- Metadata: data defining logical and physical fields, files, relationships, queries
- Three metadata types
  - Conceptual schema
  - External schema
  - Internal schema
- Data dictionary/directory system (DD/DS)
  - Stores definitions for all schemas and mappings
  - Dictionary: index and description of items; directory: location and access method
  - DDL processor; validation of definitions
  - Prevents unauthorized access to metadata; DBA reporting
  - Benefits: documentation, common validation, easier programming, standard methods
  - Reduces impact of changing DBMS
- Detailed DBMS metadata architecture
  - Each level has data definition language (DDL) component
  - External level: multiple DDLs for several programming languages
  - Conceptual level maps external to internal schemas
  - External schemas location-independent of internal schema
### 4.11.2 Database structure
- Hierarchical, network, relational, object-oriented, NoSQL
- Hierarchical model
  - Parent-child 1:N segments; logical tree; child has one parent
  - Duplication to express multiple parents; no reverse pointers
  - Examples: Windows registry, geographic information systems
- Network model
  - Set: owner record type, member record type, name
  - Multi-owner relationships; usually 1:N, 1:1 allowed
  - Complex, hard to rebuild after failure; rarely used
  - Hierarchical and network lack high-level queries; programs navigate
- Relational model
  - Based on set theory; data in tables
  - Rows are tuples (records); columns are domains/attributes (fields)
  - Keys and indexing; join operations; relationships set at retrieval time
  - Examples: Oracle, IBM DB2, Microsoft SQL Server; ERP systems
  - Advantages: easier to implement, convert, join, add relations, access control, modify
  - Table properties
    - Atomic values
    - Uniquely identifiable rows
    - Same-kind column values
    - Column and row sequence insignificant
  - Normalization rules
    - One value per attribute instance
    - Attributes elementary, no internal structure
    - Tuple: primary key plus independent attributes
    - Foreign key null or existing value: referential integrity
- Object-oriented (OODBMS)
  - Data stored as objects with code and data
  - Encapsulation and inheritance
  - Unique object identifier; loaded to virtual memory
  - Niche: engineering, science, spatial; graphics, diagrams, sounds
- NoSQL ("Not only SQL")
  - For big data and unstructured data
  - Key value
  - Column oriented
  - Graph database
  - Document-oriented (XML, JSON)
  - Time series
  - Spatial (maps, GPS)
  - Sharding: horizontal partition across servers
  - Dynamic schemas
  - Examples: MongoDB, Cassandra
### 4.11.3 Database controls
- Definition standards enforced
- Backup and recovery procedures
- Access controls incl. privileged access
- Only authorized personnel update database
- Concurrency controls: transaction commit, locking
- Accuracy, completeness, consistency rules in table/column definitions
- Database checkpoints at job stream junctures
- Database reorganization reduces unused space
- Restructuring procedures for logical, physical, procedural changes
- Performance reporting: storage, buffer size, CPU, disk configuration, deadlocks
- Minimize non-system tools and utilities
- Database activity monitoring (DAM)
- ACID properties
  - Atomicity: all or nothing 📓⭐
  - Consistency, Isolation, Durability
- Transaction journaling: sequential log of changes for reconstruction and recovery 📓
### 4.11.4 Database reviews
- Logical schema
  - Entities exist as tables or views
  - Relations through foreign keys; constraints clear
  - Nulls for foreign keys follow cardinality
- Physical schema
  - Space allocated for tables, logs, indexes, temporary areas
  - Indexes on primary or frequent-access keys
  - Justification if not normalized
- Access time reports
  - Indexes used and built correctly
  - Open searches without indexes justified
- Database security controls
  - Roles and access rights justified
  - Referential integrity rules; triggers
  - Password setting and change
  - System administrator privilege count and need
  - Auditing utility enabled and monitored
  - Access without DBMS commands or SQL
  - No admin authority for job scheduler; no embedded passwords
  - Encryption enabled
  - Production data copies authorized; masked
- Interfaces with other programs/software
  - Import/export integrity and confidentiality
  - Consistency under concurrent access
- Backup and disaster recovery procedures and controls
  - High availability and fast recovery controls
- Database-supported IS controls
  - Shared data access appropriate
  - Change procedures for DBMS software
  - Redundancy minimized; cross-referenced in dictionary
  - Dictionary integrity maintained
- IT asset management: owner, contracts/SLAs, license compliance

- Business resilience: adapt to disruptions to maintain operations and protect assets
- Align DRPs and BCPs with each other and with goals and risk tolerance
- Many have DRPs but no plans for business units during IT disruption
