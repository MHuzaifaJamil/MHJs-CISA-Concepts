### 4.1.1 Networking
- Network architecture standards give a reference model for intercomputer communication
#### Local Area Network (LAN)
- Covers small local area: one room to a few buildings
- LAN setup assessment issues
  - Cost, speed, flexibility, reliability
  - Physical transmission media and access methods
  - Traffic monitors track volumes, error rates, response times
- Physical media
  - Copper twisted-pair
    - Twisted wires reduce cross talk
    - Unshielded twisted-pair vulnerable to EMI; run in dedicated conduits
  - Fiber-optic
    - Light signals; low transmission loss; immune to EMI
    - Low wiretap risk; fragile; preferred for long-distance, high-volume runs
    - Connects floor switches to data switches; servers to SANs
  - Radio systems (wireless)
- Physical topologies
  - Bus, ring, star
  - Only star used much in new construction
  - Topology driven by ease of construction, reliability, practicality
- Media access technologies give shared access, stop monopolizing
- LAN components
  - Repeaters
    - Physical layer; amplify/regenerate signal against attenuation
    - Extend range or join segments
  - Bridges
    - Data link layer; store-and-forward; filter on MAC address
    - Reduce collision domains; software-based, less efficient than switches
  - Layer 2 switches
    - Data link layer; forward by MAC source/destination
    - Hardware ASICs; low latency; many dedicated high-speed ports
  - Routers
    - Network layer; examine IP addresses
    - Segments stay logically separate; block broadcasts
    - Software-based; can bottleneck; use load balancing
- LAN risks
  - Unauthorized changes harming data and program integrity
  - No version control
  - Poor user verification; public network access via remote connections
  - Virus and worm infection
  - Disclosure from general rather than need-to-know access
  - Masquerading as legitimate user
  - Internal sniffing
  - Internal spoofing
  - No detailed automated logs (audit trails)
  - Destruction of logging and auditing data
- LAN security capabilities
  - Declare ownership of programs, files, storage
  - Least privilege (POLP)
  - Record and file locking
  - User ID/password rules: length, format, change frequency
  - Port security: switches instead of hubs, blocks unknown MAC addresses
  - Encrypt local traffic with IPSec
- Auditor documents for LAN understanding
  - Privileged users or groups
  - LAN topology and design
  - LAN administrator/owner and their functions
  - Distinct user groups
  - Applications used on LAN
  - Procedures and standards: design, support, naming, data security
#### Wide Area Network (WAN)
- Connects geographically dispersed LANs (plants, cities, nations)
- Applies to physical and data link OSI layers
- Data flow modes
  - Simplex: one-way
  - Half duplex: one way at a time
  - Full duplex: both ways at once
- Lines can be switched or dedicated
- Implementation media
  - Fiber-optic for most high-capacity links
  - Microwave radio
    - Line-of-sight; antennae must see each other; rain affects links
    - Digital now; used on light routes; utilities use for SCADA
  - Satellite radio link
    - Transponders, 36 MHz bandwidth each
    - Weather affected; about 300 ms delay traditionally
    - Low-earth orbit (e.g., Starlink) cuts latency under 100 ms
- Transmission media comparison
  - Twisted pair: cheap, short distance under 200 feet; easy to tap, cross talk
  - Coaxial: data and video; thick, expensive, distance sensitive
  - Fiber: high bandwidth, secure, hard to tap; expensive, hard to splice
  - Radio, microwave, satellite: easy to tap; interference, noise
- WAN message transmission techniques
  - Message switching: whole message stored and forwarded; cost by length
  - Virtual circuits: logical circuit between devices
    - Switched virtual circuits (SVC): on-demand
    - Permanent virtual circuits (PVC): always-on
#### TCP/IP and its relation to the OSI reference model
- OSI: seven-layer conceptual model; layers self-contained and independent
- Each layer talks to peer layer on remote system
- Layers
  - Application: network interface for applications; not application software
  - Presentation: encryption, compression, reformatting
  - Session: establishes, manages, terminates dialogs
  - Transport: end-to-end error recovery, flow control, acknowledgements, resend
  - Network: IP addresses, routing, forwarding
  - Data link: frames, CRC error detection, MAC addresses
    - Promiscuous interface listens to all data
  - Physical: bit stream as electrical, optical, radio signals; cables, connectors
- Data traversal
  - Data travels down layers; headers/trailers added as envelope
  - Data travels up at receiver; headers/trailers removed
- OSI concepts used in LANs, WANs, MANs, and Internet
- TCP/IP predates OSI; no direct layer match
- TCP/IP protocol examples
  - Application: HTTP, FTP, SMTP, TFTP, NFS, SNMP, Telnet, DNS, DHCP
  - Transport: TCP, UDP
  - Network: ICMP, ARP, RARP, IP
  - Data link: Ethernet, FDDI, Token Ring, PPP
- Layer equipment and data unit
  - Application: gateway; data
  - Transport: layer 4 switch; segment
  - Network: router, layer 3 switch; packet
  - Data link: layer 2 switch, bridge, wireless AP, NIC; frame
  - Physical: hub, repeater, NIC; bits
#### Network administration and control
- Duties: monitor usage and throughput, load balance, respond to violations and failures
- Duties: save/restore data, scale as use grows
- Network management software accessible only to administrator
- Network OS functions
  - Local and remote terminal access
  - Shared file and print services
  - Links to hosts and servers
- Network OS user features
  - Transparent access to resources
  - Authorization checks
  - Uniform logon and logging
  - Online network documentation
- Network performance metrics
  - Latency: delay source to destination; measured with ping
  - Jitter: variance in latency
  - Throughput: bytes per second through channel
  - QoS: overall performance incl. delay, availability, packet loss
  - Error counts and retransmissions
- ISO/IEC 10040 network management tasks
  - Fault management
  - Configuration management
  - Accounting management
  - Performance management
  - Security management
- Network management tools
  - Response time reports: average, worst, best times
  - Downtime reports: line availability
    - Remedies: add/replace lines, dedicated links, backup power, access controls, monitor utilization
  - Online monitors: echo checking, status checking
  - Network monitors: real-time node status
  - Network (protocol) analyzers
    - Output: protocols, packet types, traffic volume, errors, bandwidth use
  - SNMP
    - Master console polls devices running SNMP agents
    - Monitors, configures, collects performance and security stats
#### Converged protocols
- Merge proprietary and standard protocols over existing TCP/IP infrastructure
- Benefit: simpler security, cost savings; risk: added complexity
- Fiber Channel (FC)
  - High-speed lossless block storage; to 16 Gbps, 10 km
  - Dedicated fiber infrastructure; supports OLTP databases
  - Generally more secure than IP-based storage
- Fiber Channel over Ethernet (FCoE)
  - Encapsulates FC frames in Ethernet; needs 10 Gbps or higher
  - Reliable and fault tolerant; expensive
- Multi-protocol label switching (MPLS)
  - Forwards on short 20-bit labels instead of network addresses
  - Header analyzed once; label forwarding table; class-of-service
  - Encapsulation handles many protocols
- Voice over IP (VoIP)
  - Tunnels voice/data over TCP/IP; cheaper than landline
  - Supports video; hardware or software based
- iSCSI
  - SAN protocol: SCSI commands over TCP/IP; block-level access
  - Components: initiator (host), target (storage)
  - Benefits: lower cost, flexibility, efficient transmission, security
  - Security: authentication, network isolation, integrity, confidentiality
  - Suited for disaster recovery support
#### Internet Protocol networking
- IP is connectionless
- IPv4: 32-bit dotted decimal; about 4.3 billion addresses
- IPv6: far larger address space; simpler headers; mobile-friendly
- IPv4 vs IPv6 security
  - IPv4 checksum fields used; IPv6 has none
  - IPv4 broadcasting; IPv6 multicasting
  - IPv4 no built-in encryption/authentication; IPv6 provides them
  - IPv4 manual/DHCP; IPv6 adds autoconfiguration, renumbering
  - IPv6 end-to-end integrity achievable; flow label field
- Transition strategies
  - Dual stacking: both versions on same device
  - Tunneling: IPv6 over IPv4 routing
#### Network Address Translation (NAT)
- Converts internal IPs to public IPs
- Static NAT: permanent one-to-one mapping
- Dynamic NAT: mapped from pool per session
- NAT with port address translation (NPAT): many devices share one public IP
- Benefits
  - Cost reduction and IP conservation
  - Privacy: hides topology
  - Security: only internally initiated traffic returns
  - Flexibility and scalability
  - Boundary enforcement via firewall
- Limitations
  - Time-consuming; large connection tables
  - Interferes with IPSec
  - Some applications break; added delay
#### Network devices 📓
- Router: directs traffic between networks using IP; audit routing tables 📓
- Switch: connects devices in one LAN; VLAN isolation 📓
- Gateway: connects networks with different protocols; protocol conversion 📓
- Hub, bridge, repeater ➕
- Repeater: physical layer; regenerates attenuated signal
- Bridge: data link layer; filters frames by MAC address
- Layer 2 switch: ASIC-based; MAC forwarding; cuts collision domains
- Router: network layer; blocks broadcasts and unknown-address traffic
- Hub: shared-media device; port security needs switches instead
- Layer 3 / layer 4 switch: route and segment-level switching
- Wireless access point: data link layer equipment
### 4.1.2 Computer hardware components and architectures
- Components are processing or I/O
- Processing components
  - CPU variants: microprocessor, multi-processor, multi-core
  - CPU parts: ALU, control unit, internal memory (registers)
  - Motherboard, RAM, ROM
  - Permanent storage: HDD (spinning disks), SSD (flash, no moving parts)
  - Power supply unit, cooling system, OS
  - Wi-Fi, cellular radio (LTE, 5G), Bluetooth
  - GPU: offloads graphics; used for machine learning, AI, HPC
- Input / output components
  - Input-only: keyboard, mouse
  - Input and output: touchscreen
  - Output-only: printer
- Types of computers
  - Supercomputers: highest speed; specialized calculations
  - Mainframes: shared by thousands; batch and real-time; proprietary OS
  - High-end and midrange servers: partitioning; UNIX database servers; Windows file/print
  - Personal computers: single-user workstations
  - Thin-client: minimal hardware; processing on server
  - Laptops: theft risk; battery tolerates power failure
  - Next unit of computing (NUC): small-form desktop/edge device
  - Single-board computer (SBC): one board; fixed RAM; no expansion slots
  - Smartphones, tablets, handhelds: can sync with PCs
### 4.1.3 Common enterprise back-end devices
- IoT growth: data leakage and privacy risk
- Print servers: consolidate printing across sites
- File servers: central repositories; access-control matrix
- Application (program) servers: business logic; consolidate licenses
- Web servers: pages via URLs
- Proxy servers
  - Intermediate link acting on user's behalf
  - Forward proxy: sits between client and Internet
    - Caching, traffic filtering, anonymizing client IP
  - Reverse proxy: sits between Internet and web server
    - Load balancing, security, hiding server IPs, caching
  - Open proxies: avoided; abused for phishing and spam
- Database servers: store data; others present it
- DLP gateway: inspects traffic, blocks sensitive data exfiltration
- Appliances: single-purpose, smaller, faster
  - Firewalls, IDS, IPS, switches, routers, VPNs, load balancers
### 4.1.4 USB mass storage devices
- Includes flash drives, external HDDs, SD cards
- Features: hot swapping, plug-and-play, bus power, no vendor drivers
- Risks
  - Viruses and malware vector (spyware, keyloggers)
  - Data theft from unattended unlocked PCs
  - Data and media loss
  - Data corruption from improper removal
  - Compatibility issues across USB versions
  - Physical damage
  - Loss of confidentiality; legal exposure (HIPAA)
- Security controls
  - Encryption
    - Data useless without key; still exposed if unencrypted elsewhere
  - Granular control: centrally block mass storage, allow mice and keyboards
  - Policies, procedures, user awareness program
  - Security personnel education
  - Lock desktop policy enforcement
  - Antivirus scanning of attached media
  - Use of secure (encrypted) devices only
  - Return information file; omit company details; legal disclaimer
  - Read-only switch on untrusted machines

### 4.1.6 Hardware maintenance program
- Routine cleaning and servicing; follow vendor specifications
- Includes environmental hardware: temperature, humidity, fire protection, power
- Information maintained
  - Reputable service company per resource
  - Maintenance schedule
  - Maintenance cost
  - Performance history: planned versus unplanned, executed, exceptional
- Management documents deviations from vendor specifications
- Auditor steps
  - Verify scope and objectives match business needs; note remote-site gaps
  - Ensure formal plan approved and followed
  - Identify costs exceeding budget
- Hardware monitoring reports and procedures
  - Availability reports: downtime causes (hardware, OS maintenance, environment, training)
  - Hardware error reports: CPU, I/O, power, storage failures; check intermittent errors
  - Asset management reports: inventory of network-connected equipment
  - Utilization reports
    - Mainframe-class utilization about 85 to 95 percent
    - Trends predict resource needs
### 4.1.7 Hardware reviews
- Hardware acquisition plan
  - Aligned with business requirements, enterprise architecture, IS plans
  - Acquisition criteria developed
  - Environment adequate for new hardware
  - Specifications, installation requirements, lead time documented
- Acquisition of hardware
  - Cost-benefit analysis with requests
  - Purchases routed through purchasing department
  - Written policy statements; approval forms and procedures
- IT asset management
  - Hardware tagged; owner designated; location; contracts/SLAs retained
- Capacity management and monitoring
  - Performance monitoring plan based on historical data
  - Continuous review of hardware and system software capacity
  - Equipment that auto-contacts manufacturer monitored
- Preventive maintenance schedule
  - Vendor-recommended frequency observed
  - Maintenance in off-peak periods, not during critical processing
  - Backup hardware flexible for maintenance
- Hardware availability and utilization reports; problem logs and job accounting reports
  - Reviewed for malfunctions, reruns, abnormal terminations, operator actions
