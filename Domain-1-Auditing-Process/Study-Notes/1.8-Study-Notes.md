## 1.8 Audit Data Analytics (overview)

### 1.8.0.1 Basics: what is data analytics?
- Data analytics: examining data sets to find patterns, errors, and exceptions.
  - Definition: using technology to select and analyze full data sets.
  - Use: audit or monitor key organizational data for abnormalities or variances.
  - Audit impact: tests whole populations, not just a small sample.
- Full-population testing lowers sampling risk.
- Example: testing every payment in a year, not forty sampled payments.
- Analytics helps evaluate risk and achieve compliance with control and regulatory requirements.
- Analytics works in both the planning and fieldwork phases.

### 1.8.0.2 Uses of analytics
- Determine operational effectiveness of the current control environment.
- Determine effectiveness of antifraud procedures and controls.
- Identify business process errors.
- Identify business process improvements and inefficiencies in the control environment.
- Identify exceptions or unusual business rules.
- Identify fraud.
- Identify areas where poor data quality exists.
- Conduct a risk assessment at the planning phase of an audit.
- Example: duplicate invoice matching reveals both process errors and possible fraud.
- Exam traps
  - Analytics supports auditor judgment; it never replaces the auditor's conclusion.
  - Planning-phase use is valid; analytics is not only for fieldwork.

### 1.8.0.3 Data analytics process
- Seven ordered steps: scope, obtain, validate, execute, document, review, retain.
- Step 1, set the scope.
  - Definition: define audit objectives, data needs, sources, and source reliability.
  - Audit impact: unclear scope produces irrelevant or incomplete tests.
- Step 2, identify and obtain the data.
  - Definition: request data from responsible sources, test a sample, then extract.
  - Audit impact: data owner involvement supports authenticity of the extract.
- Step 3, validate the data.
  - Definition: confirm data is sufficient and reliable for audit tests.
  - Audit impact: bad data gives false findings, so validate before testing.
  - Validate balances independently of the extracted data set.
  - Reconcile detailed data to report control totals.
  - Validate numeric, character, and date fields.
  - Verify the time period meets scope and purpose.
  - Verify all fields named in scope are in the data set.
- Example: extract total differs from the general ledger total, so completeness fails.
- Step 4, execute the tests by running scripts and other analytical tests.
- Step 5, document results: purpose, data sources, and conclusions reached.
- Step 6, review results: a qualified person confirms procedures were properly performed.
- Step 7, retain results: program files, scripts, macros or automated commands, data files.
- Exam traps
  - Validation comes before test execution; running tests on unvalidated data is wrong.
  - Independent balance validation beats trusting the extract's own totals.
  - Retention covers scripts and data, not only the final report.

### 1.8.0.4 Example analytics uses
- Combine logical access files with HR master files to confirm authorized users.
  - Audit impact: exposes terminated employees who still hold active accounts.
- Match file library settings with change management dates and authorized events.
  - Audit impact: exposes changes made outside approved change windows.
- Match ingress with egress records in physical logs to identify tailgating.
- Review table or system configuration settings.
- Review system logs for unauthorized access or unusual activity.
- Test system conversion.
- Test logical access segregation of duties (SoD).
  - Example: compare Active Directory groups with documented job descriptions.
- Exam traps
  - Access-to-HR matching targets user authorization, not system performance.

## 1.8.1 Computer-Assisted Audit Techniques (CAATs)

### 1.8.1.1 What CAATs are
- CAAT: software tool the auditor uses to gather and analyze audit data.
  - Definition: any computer-based tool or technique supporting audit evidence work.
  - Use: gain independent access to data for a set audit objective.
  - Audit impact: reliability of the data source supports reliability of findings.
- Needed when hardware, software, data structures, or record formats differ.
  - Audit impact: otherwise some evidence is almost impossible to collect.
- CAATs let the auditor gather information independently of the auditee.
- CAATs help detect irregularities or illegal acts efficiently.
- ⚠ Check: the manual says "independent access", not "no auditee help ever needed".

### 1.8.1.2 CAATs as a continuous online audit approach
- Continuous online auditing improves audit efficiency.
- The auditor must develop techniques suited to advanced information systems.
- The auditor should join system development at an early stage.
  - Audit impact: lets audit hooks and modules be designed in, not bolted on.
- The auditor should make greater use of automated tools.

### 1.8.1.3 CAAT types
- Six types: GAS, utility, debugging and scanning, test data, tracing and mapping, expert systems.
- Generalized audit software (GAS)
  - Definition: standard software that reads many databases and file formats directly.
  - Use: independent, high-level analysis of auditee data files.
  - Audit impact: auditor avoids relying on auditee-written extracts.
  - Example: an auditor runs duplicate-payment checks on a vendor payment file.
- GAS functions
  - File access: reads different record formats and file structures.
  - File reorganization: indexing, sorting, merging, and linking with another file.
  - Data selection: global filter conditions and selection criteria.
  - Statistical functions: sampling, stratification, and frequency analysis.
  - Arithmetical functions: arithmetic operators and functions.
  - Features include stratification, sequence checking, duplicate checking, and recomputation.
- Utility software
  - Definition: a subset of software, such as DBMS report generators.
  - Use: gives evidence about system control effectiveness.
  - Audit impact: quick evidence, but depends on trusted, unaltered utilities.
- Utility software uses
  - Tests of details of transactions and balances.
  - Analytical review procedures.
  - Compliance tests of IS general controls and application controls.
  - Network and OS vulnerability assessments.
  - Penetration testing.
  - Application security testing and source code security scans.
- Debugging and scanning software, plus application tracing and mapping, complete the list.
  - ⚠ Check: the manual names these types but gives no further detail here.
- Test data
  - Definition: sample data the auditor runs through a program.
  - Use: assess whether logic errors exist and objectives are met.
  - Audit impact: shows program logic works, not that production data is clean.
- Audit expert system
  - Definition: a query-based system built on senior auditors' knowledge.
  - Use: guides auditors at all levels during an audit.
  - Audit impact: spreads senior judgment; quality depends on its knowledge base.
- Exam traps
  - GAS reads data independently; relying on auditee reports weakens independence.
  - Test data checks logic; it does not validate live data completeness.

### 1.8.1.4 Cost-benefit factors before adopting CAATs
- Ease of use for existing and future audit staff.
- Training requirements.
- Complexity of coding and maintenance.
- Flexibility of uses.
- Installation requirements.
- Processing efficiencies.
- Effort to bring source data into the CAAT.
- Integrity of imported data, protected by safeguarding its authenticity.
- Record the time stamp of data downloaded at critical processing points.
  - Audit impact: sustains credibility of the review.
- Permission to install software on auditee servers.
- Reliability of the software.
- Confidentiality of the data being processed.
- Exam traps
  - Weigh costs and benefits first; buying a tool before this analysis is wrong.

### 1.8.1.5 CAAT documentation and data handling
- Retain online reports detailing high-risk issues for review.
- Retain commented program listings.
- Retain flowcharts.
- Retain sample reports.
- Retain record and file layouts.
- Retain field definitions.
- Retain operating instructions.
- Retain descriptions of applicable source documents.
- Reference CAAT documentation to the audit program.
  - Audit impact: links each procedure to the objective it serves.
- Request read-only access to production data.
- Manipulate copies of production files in a controlled environment.
- Download production data to a standalone platform for analysis.
  - Audit impact: insulates production systems from adverse impact.
- Example: auditor tests a copy of payroll data offline, never live tables.
- Exam traps
  - Read-only access is the first answer; update access is never justified.
  - Testing on production files risks unauthorized change and system disruption.

## 1.8.2 Continuous auditing and monitoring

### 1.8.2.1 Definitions
- Continuous auditing
  - Definition: the auditor tests in real-time or near-real-time.
  - Use: report results far sooner than a traditional audit.
  - Audit impact: short gap between event, evidence, and reporting.
- Continuous monitoring
  - Definition: the organization observes performance of processes, systems, or data.
  - Use: management's day-to-day oversight, such as real-time antivirus or IDS.
  - Audit impact: lacks independence and objectivity, so never replaces audit.
- Continuous assurance
  - Definition: result when continuous auditing and monitoring both operate.
  - Audit impact: auditing must stay independent of monitoring activities.
- Continuous auditing often precedes management adopting continuous monitoring.
- Audit often hands its techniques to the business to run monitoring.
- Exam traps
  - Monitoring is a management control; it is not an independent audit.
  - Handing techniques to the business does not transfer audit independence.

### 1.8.2.2 How it is built and used
- Tools are built into many ERP packages and most OS and network security packages.
- Configured with rules, parameters, and formulas, they output exception lists on request.
- Requires a defined exception or "dangerous" condition.
  - Example: access permissions are only risk-free if SoD rules are well defined.
- Vague conditions, like odd database update sequences, are harder to define.
- Validate the source of the data and the possibility of manual changes.
  - Audit impact: manually altered source data corrupts automated conclusions.
- Intrinsic edge: catches control problems as they occur, preventing negative effects.
- Also reduces audit delays, planning time, and overhead of segmented work.
- Exam traps
  - Real-time detection is the advantage; periodic audit finds issues afterward.

## 1.8.3 Continuous auditing techniques

### 1.8.3.1 Purpose and general limits
- Useful in time-sharing environments with many transactions and scarce paper trails.
- Evaluate operating controls without disrupting normal operations.
- Reduce the time lag between misuse and detection.
- Example: reporting a withdrawal from an inoperative account promptly.
- Provide only limited assurance; they are not a cure for all control problems.
- Selection depends on system complexity and the auditor's understanding.
- Need full top management support, dedication, experience, and technical knowledge.
- Layers and settings need continual adjustment and updating.
- Tools run in parallel with normal processing, capturing real-time data.

### 1.8.3.2 The five automated techniques
- ➕ Outline shorthand "embedded audit modules, snapshots, audit hooks, SCARF" is covered below.
  - ⚠ Check: manual supports all; five techniques are SCARF/EAM, snapshots, hooks, ITF, CIS.
- SCARF/EAM
  - Definition: audit software embedded inside the host application system.
  - Use: selective monitoring when regular processing cannot be interrupted.
  - Audit impact: gathers evidence continuously inside the live application.
- Snapshots
  - Definition: tagged transactions with recorded "pictures" of their path, input to output.
  - Use: needed when an audit trail is required.
  - Audit impact: auditor reviews recorded processing steps afterward.
- Audit hooks
  - Definition: logging or monitoring triggers embedded in applications as red flags.
  - Use: when only select transactions or processes need examination.
  - Audit impact: prompts auditors and security to act before problems grow.
- Integrated test facility (ITF)
  - Definition: dummy entities set up in the auditee's production files.
  - Use: process test transactions alongside live ones in normal runs.
  - Audit impact: compare output with independently calculated results.
  - Example: a fictitious customer account receives test invoices during live billing.
  - Risk: dummy data must not contaminate real financial totals.
  - ⚠ Check: manual's use-case chart for ITF reads "not beneficial to use test data".
- Continuous and intermittent simulation (CIS)
  - Definition: simulator mimics application logic as each transaction is processed.
  - Use: audit only transactions meeting predetermined criteria.
  - Audit impact: simulator waits until the next qualifying transaction appears.
- ⚠ Check: figure complexity ratings are garbled in source; verify in printed manual.
- Exam traps
  - ITF test transactions run with live data; snapshots tag real transactions.
  - Embedded modules fit when processing cannot stop; audit trail need points to snapshots.
  - Hooks examine selected items; CIS examines items meeting set criteria.
  - Compare ITF output to independent calculation, not to the system's own result.

### 1.8.3.3 Data levels and supporting technologies
- Techniques must work at single input, transaction, and database levels.
- Supporting technologies
  - Transaction logging.
  - Query tools.
  - Statistics and data analysis.
  - DBMSs.
  - Data warehouses, data marts, and data mining.
  - Intelligent agents (bots): software that monitors settings and sends threshold alerts.
  - EAM.
  - Neural network technologies.
  - XBRL: Extensible Business Reporting Language, a standard for reporting data.
- Intelligent agents allow flexible, dynamic analysis and continuous monitoring of settings.

### 1.8.3.4 Disadvantages and AI use
- Difficulty and cost.
- Control experts and auditors may hesitate to trust tools over judgment.
- Mechanisms must remove false positives and false negatives.
  - Definition: false positive flags a good item; false negative misses a bad one.
  - Audit impact: false negatives are the dangerous errors; auditors miss real issues.
- AI/ML automates fraud detection, data quality checks, and negative-news screening.
- AI/ML can cut manual overhead and reconciliation effort in large banks.

## 1.8.4 Artificial Intelligence in IS audit 📓

### 1.8.4.1 Why use AI
- AI/ML can increase audit efficiency or decrease audit risk.
- Efficiency comes from automating work paper markups and data manipulation.
- Risk falls through larger samples and more analysis time.
- Robotic process automation (RPA): software robots performing rule-based repetitive tasks.
- Enablers: NLP, natural language generation, predictive analysis, and RPA.

### 1.8.4.2 AI across the audit lifecycle
- Plan: preselect audit candidates, review issues, understand the process landscape.
- Scope: automate analysis and summary of policies and SOPs.
- Fieldwork: data sample testing, rule engines, and fraudulent data detection.
- Report: auto-generate reports and update the business unit's risk profile.
- Example: NLP reads hundreds of policy pages and drafts initial scope notes.

### 1.8.4.3 Benefits 📓
- AI rapidly analyzes large datasets. 📓⭐
- AI automates repetitive tasks. 📓
- AI identifies anomalies automatically. 📓
- Exam traps
  - Efficiency from large-dataset speed is the primary benefit.
  - "Guarantees compliance", "replaces auditors", or "automates decisions" are false benefits.

### 1.8.4.4 Limits and responsibilities 📓
- Humans retain professional judgment. 📓
- AI does not guarantee compliance. 📓
- A person must interpret AI/ML results at some point.
- Exam traps
  - Complete elimination of human auditors is always the least likely benefit.

### 1.8.4.5 Audit algorithms
- Algorithm
  - Definition: a defined way to solve a specific problem.
  - Use: repeatable steps that automate analysis.
  - Audit impact: auditor must understand logic to judge reliability.
- Humans play a decisive role in algorithm design and metrics.
- The auditor asks questions, interprets results, and expects errors.
- Audit as an algorithm
  - Obtain the "as is" and "as should be" versions.
  - Perform operations needed to enable comparison.
  - Perform the comparison.
  - Assess results and their significance.
- Review and adapt algorithms as needs change.
- Homomorphic encryption
  - Definition: lets software compute on encrypted data without decrypting it first.
  - Use: privacy-preserving processing, such as in cloud analytics.
  - Audit impact: protects confidentiality, but is inefficient and storage-heavy.
- ⚠ Check: the manual cites homomorphic encryption only as an efficient-algorithm example here.
- AI/ML techniques for audit
  - Document classification: labels documents or text segments by topic.
  - Text summarization: builds a natural-language summary of documents.
  - Topic analysis: finds unique topics linking documents or sections.
  - Search and retrieval: finds documents matching topics in search criteria.
  - Statistical analysis: evaluates term, phrase, or topic trends.
  - Sentiment analysis: extracts author sentiment from text.
- Example: sentiment analysis flags unhappy tone across incident reports.

### 1.8.4.6 Interpretation of AI/ML results
- A person should interpret results.
- Validate data inputs at implementation and periodically.
  - Audit impact: incomplete or inaccurate inputs make the tool useless.
- Obtain raw system data to check tool conclusions where possible.
- Understand statistical significance of results.
- Results should represent the entire audit universe.
- Support conclusions with evidence, not computer output alone.
- Beware assumptions and caveats hidden in results.
- Example: facial recognition on blurry images wrongly identified suspects.
- Exam traps
  - Computer output alone is never sufficient audit evidence.

### 1.8.4.7 AI/ML audit risks and considerations
- AI/ML is an evolution of CAATs; the same considerations apply.
- Inadequate testing gives questionable outcomes; add human-led testing.
- AI programs are often proprietary with thin documentation.
- Training data must be correct, adequate, and cover usual and unusual cases.
- Trusting the machine is justified only after exhaustive testing.
- Human-built tools carry human ethics and bias.
- Model drift 📓➕
  - Definition: model accuracy falls over time as conditions change.
  - Use: monitor accuracy and retrain on current data.
  - Audit impact: stale models give unreliable audit conclusions.
- Fix drift with regular data updates. 📓⭐➕
- Algorithmic bias 📓➕
  - Definition: unfair or skewed outputs from the model.
  - Audit impact: biased samples or findings undermine fairness and objectivity.
- Fix bias with diverse, representative training data. 📓⭐➕
- Legal compliance with data protection laws. 📓⭐➕
- Pseudonymising training data. 📓➕
  - Definition: replacing identifiers with codes or tokens.
  - Audit impact: lowers breach exposure but is not full protection.
- ⚠ Check: manual 1.8.4 never uses the terms model drift, algorithmic bias, or pseudonymisation.
- ⚠ Check: manual only says bias comes from human judgment; fixes are from notes.
- ⚠ Check: legal compliance as top item is from user's notes, not manual.
- Exam traps
  - Legal compliance outranks pseudonymisation when asked for the most important consideration.
  - Diverse, representative data fixes bias; a single data source worsens it.
  - Regular data updates fix drift; extra algorithms or staff training do not.
  - Parallel manual audits do not remove bias already inside the model.

## Takeaway
- Validate data first, then test, document, review, and retain scripts.
- CAATs need read-only access and work on copies, never production.
- Continuous monitoring is management's control and never replaces independent audit.
- Match technique to need: EAM, snapshots, hooks, ITF, CIS.
- AI speeds analysis, but humans judge, interpret, and keep evidence.
- Fix drift with fresh data, bias with representative data.
