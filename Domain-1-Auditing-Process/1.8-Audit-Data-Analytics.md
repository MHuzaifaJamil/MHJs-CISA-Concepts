# 1.8 Audit Data Analytics

> **Markers:** 📓 = in my Google Doc notes · ⭐ = frequently tested · ➕ = not in the review manual, verify · unmarked = gap to study. Numbering follows the ISACA CISA Review Manual 28th Ed.

- Analyze full data sets to audit or monitor continuously
- Uses of analytics
  - Determine operational effectiveness of controls
  - Determine effectiveness of antifraud controls
  - Identify business process errors
  - Identify improvements and inefficiencies
  - Identify exceptions or unusual business rules
  - Identify fraud
  - Identify poor data quality
  - Risk assessment at planning phase
- Data analytics process
  - Set the scope
  - Identify and obtain the data
  - Validate the data
    - Validate balances independently of extracted data
    - Reconcile detailed data to report control totals
    - Validate numeric, character and date fields
    - Verify time period of data set
    - Verify all required fields included
  - Execute the tests
  - Document the results
  - Review the results
  - Retain the results
    - Program files, scripts, macros, data files
- Example analytics uses
  - Combine logical access files with HR master files
  - Match file library settings with change management dates
  - Match ingress and egress records to find tailgating
  - Review table or system configuration settings
  - Review system logs for unauthorized access
  - Test system conversion
  - Test logical access SoD with Active Directory and job descriptions
### 1.8.1 Computer-Assisted Audit Techniques (CAATs)
- CAATs as a continuous online audit approach
  - Improve efficiency through continuous online auditing
  - Auditor involved in early system development
- Needed for differing hardware, software, data structures
- Enable independent data access and analysis
- CAAT types
  - Generalized audit software (GAS)
  - Utility software
  - Debugging and scanning software
  - Test data
  - Application software tracing and mapping
  - Expert systems
- GAS functions
  - File access
  - File reorganization
  - Data selection
  - Statistical functions
  - Arithmetical functions
  - Features include stratification, sequence and duplicate checking, recomputation
- Test data: assess logic errors and program objectives
- Audit expert system built on senior auditor knowledge base
- Utility software uses
  - Tests of transaction details and balances
  - Analytical review
  - Compliance tests of general and application controls
  - Network and OS vulnerability assessments
  - Penetration testing
  - Application security testing and source code scans
- Cost-benefit factors before adopting CAATs
  - Ease of use and training
  - Coding complexity and maintenance
  - Flexibility and installation requirements
  - Processing efficiency
  - Effort to import source data
  - Integrity and authenticity of imported data
  - Time stamp of data downloaded
  - Permission to install on auditee servers
  - Software reliability
  - Confidentiality of data processed
- CAAT documentation to retain
  - Online reports on high-risk issues
  - Commented program listings
  - Flowcharts
  - Sample reports
  - Record and file layouts
  - Field definitions
  - Operating instructions
  - Source document descriptions
- Reference CAAT documentation to audit program
- Request read-only access to production data
- Work on copies in a controlled standalone environment
### 1.8.2 Continuous auditing and monitoring
- Continuous auditing
  - Real-time or near-real-time tests and reports
  - Short lapse between event, evidence and reporting
  - Should be independent of monitoring
- Continuous monitoring
  - Organization observes performance of processes, systems, data
  - Example: real-time antivirus or IDS
  - Lacks independence, never a substitute for audit
- Continuous assurance when both occur
- Audit often hands techniques to business for monitoring
- Built into ERP, OS and network security packages
- Requires defined exception conditions, such as SoD
- Validate source of data and possible manual changes
- Intrinsic edge over periodic audit: catches problems as they occur
### 1.8.3 Continuous auditing techniques
- Embedded audit modules, snapshots, audit hooks, SCARF ➕
- Five automated techniques
  - SCARF/EAM
    - Embedded audit software in host application
    - Selective monitoring
    - Used when regular processing cannot be interrupted
  - Snapshots
    - Tag transactions and record path from input to output
    - Used when audit trail is required
  - Audit hooks
    - Hooks in applications act as red flags
    - Used when only select transactions need examination
  - Integrated test facility (ITF)
    - Dummy entities in production files
    - Test transactions processed with live ones
    - Compare output to independent calculations
  - Continuous and intermittent simulation (CIS)
    - Simulator audits transactions meeting set criteria
    - Used when transactions meeting criteria need examination
- Reduces lag between misuse and detection
- Gives only limited assurance, not a cure-all
- Selection depends on system complexity and auditor understanding
- Needs management support and technical knowledge
- Techniques operate at input, transaction and database levels
  - Transaction logging
  - Query tools
  - Statistics and data analysis
  - DBMSs
  - Data warehouses, marts, mining
  - Intelligent agents (bots)
  - EAM
  - Neural networks
  - XBRL
- Disadvantages
  - Difficulty and cost
  - Hesitation to trust tools over judgment
  - Need to eliminate false positives and false negatives
- AI/ML used for fraud detection, data quality checks, screening
### 1.8.4 Artificial Intelligence in IS audit 📓
- Increases efficiency and reduces audit risk
- Larger sample sizes and more time for analysis
- RPA and AI across audit lifecycle
  - Plan: preselect candidates, understand process landscape
  - Scope: automate analysis of policies and SOPs
  - Fieldwork: data testing, rule engine, fraud detection
  - Report: auto-generate reports, update risk profile
  - Enablers: NLP, natural language generation, predictive analysis, RPA
#### Benefits
- Analyzes large datasets rapidly 📓⭐
- Automates repetitive tasks 📓
- Identifies anomalies automatically 📓
#### Limits and responsibilities
- Humans retain professional judgment 📓
- AI does not guarantee compliance 📓
#### Audit algorithms
- Algorithm: a way to solve a specific problem
- Humans decide algorithm design and metrics
- Auditor asks questions, interprets results, expects errors
- Audit as algorithm
  - Obtain "as is" and "as should be"
  - Perform operations needed for comparison
  - Perform the comparison
  - Assess results and significance
- Review and adapt algorithms as needs change
- Homomorphic encryption: compute on encrypted data
- AI/ML techniques for audit
  - Document classification
  - Text summarization
  - Topic analysis
  - Search and retrieval
  - Statistical analysis
  - Sentiment analysis
#### Interpretation of AI/ML results
- Person should interpret results
- Validate data inputs at implementation and periodically
- Obtain raw data to check conclusions
- Understand statistical significance and representativeness
- Support conclusions with evidence, not output alone
- Beware assumptions and caveats
#### AI/ML audit risks and considerations
- AI/ML is an evolution of CAATs
- Inadequate testing gives questionable outcomes
- Proprietary algorithms: limited documentation
- Training data must be correct and adequate
- Over-trust in the machine's answer
- Human bias and ethics carried into tools
- Model drift: accuracy degrades over time 📓
- Fix drift with regular data updates 📓⭐
- Algorithmic bias: unfair or skewed outputs 📓
- Fix bias with diverse, representative training data 📓⭐
- Legal compliance with data protection laws 📓⭐
- Pseudonymising training data 📓
